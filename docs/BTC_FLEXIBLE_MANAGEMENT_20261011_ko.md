# BTC 유연한 보유·보호 관리

사용자 승인: 2026-10-11 제안 종합 후 “구현 및 배포”. M0/M1 안전 경계와 M2 재생 수리,
M4 보유 정책·M5 관측을 분리한다. 실자금 전환이나 수익 보장 승인이 아니다.

## 승인 범위와 불변 조건

- 회복 0.5%→1%→2% 단계는 유지하되, 각 단계의 새 비용 후 수익 거래 2건으로 승격한다.
  완전히 종료·정산된 양수 거래만 센다. 0원/미체결/과거 집계는 새 규칙 실적으로 재해석하지 않는다.
  승격은 다음 신규 OPEN부터다. 기존 보유 위험 한도, 손실 시 강등, 일중/운영 중단은 유지한다.
- 구조적 무효화 위치를 먼저 선택하고 수량으로 위험을 조정한다. 회복 단계는 작은 수량이지
  기계적으로 가까운 SL을 뜻하지 않는다. 정상 눌림에서 WAIT/부분 SL/EXIT를 비교한다.
- 15분은 최소 전략 프레임이며 30분·1시간을 우선한다. 상위 배열과 실제 가격/MA 기울기를
  구분하고, 초기 발산·가격 진행·목표 경로 여유와 둔화·반응을 TP 배분에 연결한다.
- 기존 Full SL·부분 SL·reduceOnly 실행을 유지한다. SL 되돌림은 아래의 제한적 예외뿐이다.
  고정10배, 비용·미체결 포함 시나리오 한도, 이익으로 한도 보충 금지, 한 시나리오 원칙은 불변이다.

## 제한적 SL 되돌림 계약

새 OPEN에서만 호스트가 최초 SL과 action ID를 영속 저장한다. 구형 active에 없는 경계를
복원하거나 현재 SL로 대신하지 않는다. 그런 포지션은 종료 전까지 완화가 금지된다.

모델은 stop_revision에 현재 입력 ID와 새 구조 근거를 제시한다. 근거 문자열은 경제적 타당성
입증이 아니며, 호스트는 수치·권한·실행 조건만 강제한다. 실제 되돌림은 ADJUST여야 하고,
새 진입/미체결 진입/취소 요청이 없어야 한다. 이미 이전 SL에 닿았다면 완화하지 않는다.

최초 SL보다 더 불리해질 수 없고, 이미 소진한 손실·비용과 남은 **전량** 위험이 기존 한도
안이어야 한다. 부분 SL의 미래 체결을 가정해 위험을 할인하지 않는다. 명시적 soft 회복 허가는
유지하지만 일중/운영 중단·미확정 체결·회계·보호·낡은 원본 입력은 위험 증가를 허용하지 않는다.

거래소 변경 직전 원본 계좌 fingerprint/입력 신선도/이전 실제 SL을 재검사한다. 시도 기록을
먼저 저장하고, Full SL을 in-place로 한 번 변경한다. 실제 가격·전량 보호 확인 뒤 상태와 영수증을
원자적으로 저장한다. ACK만으로 성공이라고 하지 않는다.

불확실하면 원래의 더 강한 보호로 복구한다. 복구·체결·회계가 확인된 실패 의도만
ABORTED_RESTORED로 종료해 정규 판단을 재개한다. 미확정 완화 재전송은 금지한다.
일반 _ensure_protection과 broker_stop_regressed 보호는 느슨하게 바꾸지 않는다.

## 비용·알림

현재 Mark와 SL의 예상 손익을 동일한 보수적 미래 비용 기준으로 비교한다. 이 값은 실제 수수료율이
아니며, 실제 청산비용 추정이 없으면 미확인으로 남긴다. 원래 위험 비용 가정은 낮추지 않는다.
가격 기준 이익권 SL을 순이익 보장이라고 부르지 않고, 확인된 SL 완화는 전후 가격과 위험 증가를 표시한다.

## 재생 오류와 실험 분리

기존 A288회 이후 frozen 불일치는 최초 actual propose의 계약 모듈 lazy import가 재생에는
없었던 문제다. 첫 입력을 바꾸지 않고 같은 시점에 import한다. 별도 프로세스 회귀로 검증한다.
semantic/source/identity 검사나 원본 tape를 고쳐 통과시키지 않는다.

기존 c5d/074 비교와 이번 새 정책의 경제 비교는 다른 실험이다. 과거 원본·미완료 영수증은
보존한다. 과거 known 손실/회복 사례는 개발 표본이며 독립 holdout으로 세지 않는다.

## 검증과 채택 범위

기존 동작 회귀, 롱/숏 대칭, legacy/anchor 경계, 무진입 위험 초과, stale account/input,
UNKNOWN·취소/부분체결 race, 거짓 ACK, 변경 후 timeout·재시작, 중복 제출, 부분 SL dust,
보호 유지·실패 복구 후 WAIT/EXIT 재개를 주문 없는 격리 환경에서 검사한다.
실제 보유 입력과 급락/강한 지속/수렴 반례에서 판단 지침을 비교한다. 테스트 개수나 WAIT 증가를
수익 개선으로 해석하지 않는다. 전체 테스트·CI·서버 스모크·첫 정규 실행을 별도로 기록한다.
운영은 데모 관측이며 M5 수익 개선은 여전히 미입증이다.
