# 현재 매매 흐름과 시간봉 우선순위 (M3/M4)

사용자 승인: 현재 포지션의 흐름을 이어 판단하고, 방향성 참고 우선순위를
30분 > 1시간 > 4시간 > 12시간 > 일봉 > 주봉으로 분명히 한다.

## 범위와 연결

기존에도 모든 장기 시간봉을 입력에 넣고 MA10/35 장애물을 확인하도록 지시했다.
이번에는 순서를 정성적 중요도로 명시한다. 검증되지 않은 40%/20% 같은 수치나
승률을 만들지 않는다. 15분은 타이밍 보조다. 주봉이 낮은 우선순위라도 가까운
지지·저항의 실제 장애물은 무시하지 않는다. 강한 30분 추세도 확정된 실패·위험
한도를 무시하는 권한이 아니다. 확인되지 않은 시간봉은 UNKNOWN이다.

ClickStack은 사건 검색·연결의 입구이며 원문 저장소 자체가 아니다. 매 5분 판단은
외부 검색 장애·전송 지연에 종속되지 않도록 동일 사건의 로컬 원장으로 현재
scenario_id만 prefetch한다. 최초 계약/OPEN, 최초 확인 체결, 보유·목표 관측,
요청한 계획 변경과 이행 상태, 정성 판단 변화와 미해결 재평가 조건을 제한된
position_flow로 연결한다. 전체 과거 매매를 임의로 일반화하거나 별도 LLM 요약을
호출하지 않는다. 과거 다른 시나리오의 유사 사례 검색은 이번 운영 입력에 넣지 않는다.

한 번의 초기 판단 문맥에 만들고 저장한 뒤 SINGLE/DRAFT/SELECT의 공통 원본으로 쓴다.
각 요청이100KB를 넘으면 모델 전용 사본에서 오래된 이력 항목만 통째로 줄이고,
생략을 표시한다. 단계별 잔여 용량에 따라 전달된 과거 항목 수는 다를 수 있다.
필수 시세·회계·후보는 줄이지 않으며 이들만으로 초과하면 기존 입력 제한을 유지한다.
보호 루프나 최신 주문 검산에서 외부 검색/새 히스토리 요약을 하지 않는다.
원장과 원문은 보존하며 요약에는 범위·생략·누락을 표시한다. 모든 과거를 무제한
프롬프트에 넣지 않고 원본과 최근 의미 있는 변화로 제한한다.

## 일관성과 안전

- 최초 진입 목적은 고정하지만 과거 의견은 현재 사실이 아니다. 잘못된 판단은 정정한다.
- 주문 계획·요청·PENDING은 체결이나 설치 완료가 아니다. 관측 수량 변화로 체결을 만들지 않는다.
- 현재의 검증된 보유/목표/회계가 우선이다. 과거 익절·비용을 다시 합산하지 않는다.
- 자료 누락은 모름이다. 선택적 히스토리 누락만으로 청산·거래 차단을 강제하지 않는다.
- FAILED 집행·리스크·모델·10배·시세 수집·5분/1분 스케줄·TP/SL 공식은 바꾸지 않는다.
- history reason에 은퇴한 시간봉이 있어도 현재 시세 근거로 재사용하지 않는다.

## 검증 기준

같은 시나리오 결합, 미래·거절 응답 제외, 최초 anchor와 최근 상태 변화 보존,
멀티바이트 입력 상한·명시적 생략, 재시작, 실제 SINGLE/DRAFT/SELECT 복원,
원장 조회의 무쓰기/무네트워크, 결측 시간봉과 장기 장애물의 반례를 검증한다.
실제 모델 비교는 주문 없는 고정 과거 입력으로 수행하며 경제성 입증으로 부르지 않는다.
구현·테스트·CI·배포·자연 판단·수익 개선을 분리한다. M5 수익 개선은 미입증이다.

## 2026-10-19 운영 확인에서 발견한 기존 입력 장애 (M0/M3)

PR #1055의10:56 배포 후 첫 자연 판단 확인 중,09:00부터 이미25개 판단이
`research_input_size`로 모델 호출 전에 차단됐음을 테이프 원문으로 확인했다.
보호는 별도 확인됐으며 이 오류를 새 매매 흐름 기능이 시작한 것으로 해석하지 않는다.

복구 관측의 changed_evidence가 baseline/current에 이미 있는 이전 값·현재 값을
다시 담고 있었다. 입력 projection v5는 정확히 같은 값임을 확인할 때만 공유 참조로
바꾼다. 코드가 선택한 변경 경로 목록과 공통 접두사를 명시하며, 모델에게 변경 항목을
찾거나 숫자를 다시 계산시키지 않는다. 타입·순서·해시로 원본을 정확히 복원한다.
v1~v4 복원·표/후보/영수증 참조와 호환하고100KB 제한·출력 스키마·위험 규칙은 유지한다.

실패 원문2건의 DRAFT는101,538/101,403 bytes에서98,711/98,505 bytes로 줄고,
가짜 모델 호출·정확 재생을 통과했다. 별도 실제 모델1회로 얻은 OPEN 후보를 호스트가
검산한 SELECT 입력도96,579 bytes로 통과했다. 선택은 가짜 WAIT였으며 주문은 없다.
경제 성과를 검증한 것이 아니다. 누적 과거 오류·원본 테이프는 삭제하지 않는다.

무호출·clock 연산만 있는 정확한 입력 크기 실패는 기존 input_size 진단으로 표시한다.
이미 모델을 호출한 뒤의 실패를 무호출로 바꾸지 않는다. 전체 테스트·CI·후속 배포·
자연 복구는 이 별도 수리 PR의 근거로 확인한다.
