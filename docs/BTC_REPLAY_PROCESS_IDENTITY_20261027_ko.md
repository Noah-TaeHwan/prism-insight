# M2 격리 재생의 프로세스 식별값

목표 계약 보유 재생을 다른 프로세스에서 실행하면 판단·계좌 결과는 같아도 `incident_epoch_transport_v1.owner_pid`에 실제 PID가 저장되어 전체 감사 해시가 달랐다. 같은 프로세스의 fresh/frozen 검사로는 발견되지 않았다. 원 실패 자료는 수정하거나 성공으로 바꾸지 않는다.

`economic-reject-goal-v2` 프로필은 새 계약 식별 방식 `EXACT_REPLAY_UUID5_CALLSITE_PID0_V2`를 기록하고, 격리 재생 중 실행 모듈의 PID 조회만0으로 고정한다. 0은 실제 호스트 PID가 아닌 재생 전용 식별값이다. 기존 UUID 호출위치별 식별 방법은 유지한다. 공유 `os` 모듈을 수정하지 않으며 정상 운영과 기존 프로필은 실제 PID를 사용한다. 범위 종료·예외 발생 시 모듈 참조를 복구하고 기존 동시 재생 금지 잠금을 유지한다.

실행 모듈의 os import를 함수 내부에서 모듈 수준으로 옮겨 기존 UUID와 같은 제한된 모듈 어댑터 방식을 사용한다. 주문·가격·권한·위험 로직은 바꾸지 않는다. 새 감사행은 전체가 여전히 해시에 포함된다. 비교에서 임의 필드를 제외하거나 기존 기록의 PID를 덮어쓰지 않는다.

서로 다른 실제 Python 프로세스에서 합성 진입·보유·native 주문 감사행을 생성한 뒤 전체 결과 해시가 같은지 검증한다. 공유 os.getpid 불변, 예외 후 복구, 기존 프로필 보존, 새 프로필을 옛 식별 방식으로 위장한 등록 거절도 검사한다. 모델·실주문 호출은0이다.

재생은 새 연구 DB와 고정 소스에서만 수행한다. 운영 거래 worker와 같은 프로세스에서 이 범위를 쓰거나 연구 DB를 운영 DB로 재사용하지 않는다. 과거 실계좌·incident epoch를 재현했다는 주장이 아니다. 수익성·실제 체결가격 parity·M5는 별도다.
