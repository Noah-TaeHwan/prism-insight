## 근거와 반례

최근 체결·정산 손실 2건과 수익 2건을 정산 저장 순서로 고정해 선택했다.
OPEN intent/action/input_id와 당시 저장 판단을 정확히 연결했다. 각 최초 체결은
판단 후 약 37~46초다. 차트는 판단 이전 저장된 캔들·own-time MA와 당시 진행봉을
사용했으며 새 검색 자료로 과거 수신 데이터를 대체하지 않았다.

- 10/17 21:40 SHORT, 원장 순손익 −3.32 USDT: 30분 확정 MA 간격 25.86,
  진행봉 6.09달러. 확정 5봉 연속 축소·15봉 압축, 1시간 확정 11봉 연속 축소.
  큰 움직임 후 가격 범위가 겹치고 이평 간격이 좁아진 상황이라는 가설에 부합한다.
- 10/17 11:30 SHORT, −12.66: 30분은 12봉 수렴 후 확정 간격이 6.08달러
  증가했고 진행봉도 2.73달러 증가했다. 1시간은 수렴 중이다. 순수 수렴만으로
  설명할 수 없으며 WIDENING 부호와 강한 가격 발산은 구분해야 한다.
- 10/17 00:55 SHORT, +1.05: 30분 긴 압축 뒤 실제 하락 진행·진행봉 간격 확대가
  있었으나 1시간은 수렴했다. 모든 프레임의 간격 확대를 요구하면 놓칠 수 있다.
- 10/16 10:50 SHORT, +1.34: 30분 수렴·BETWEEN이어도 결과는 양수였다.
  횡보·수렴 전부를 실패나 금지로 분류할 수 없다.

이는 저장 체결/정산 근거의 개발 복기이며 독립 회계·인과·수익 개선 증명이 아니다.
첫 손실의 기존 설명도 수렴과 제한적 probe를 이미 인식했다. 문제를 '모델이
수렴 정보를 전혀 못 받았다'고 단정하지 않는다.

## 가설·궁합·최소 변경

1. 가설: 기존 배열/가격 위치보다 현재 가격 진행과 간격 변화의 관계를 먼저
   비교하면 약한 수렴 구간의 신규 노출을 더 일관되게 판단할 수 있다.
2. 반증: 정상 눌림·새 돌파를 일괄 차단하거나, 더 가까운 TP/작은 비중만으로
   구조적 근거가 없는 진입을 정당화하면 실패다. 두 손실을 반드시 WAIT로 만들지 않는다.
3. 변경 층: `scenario_llm.FLAT_ENTRY_PROMPT`만 보완한다. 결정론 게이트·스냅샷·
   호스트 위험 계산에도 동일한 벌점을 복제하지 않는다.
4. 실제 경로: SYSTEM + MA_STRUCTURE + flat일 때만 FLAT_ENTRY → allocation 변환 →
   DRAFT → 호스트 계산 → SELECT → 기존 최신 계좌/권한 guard다.
5. 보존: 유효한 가격 돌파는 이평 교차·추가 확정봉·두 주력 프레임 만장일치를
   기다리지 않아도 된다. 진행봉은 잠정적이다. 상위 프레임 방향만으로 차단하지 않는다.
6. 경제성: 구조적 근거가 있는 후보를 추측 비용만으로 버리지 않고 기존 호스트
   계산에 맡긴다. 작은 위험 배분/가까운 실제 장애물 앞 TP는 선택지이지 의무가 아니다.
   SL을 억지로 좁히거나 강한 잔량 추세 추종을 없애지 않는다.

활성 보유·미체결 시나리오에는 flat 부록이 붙지 않는다. 기존 보호/청산 규칙,
10배·회복 한도·최대 위험·모델·5분 판단/1분 보호와 실자금 비활성을 유지한다.
KR/US 주식 전략이나 다른 프롬프트도 변경하지 않는다.

## 사전 고정 검증

- 양방향 정상 발산·수렴 정체·정상 눌림·진행봉과 확정봉 차이를 다룬다.
- 실제 조립된 두 모델 단계에 flat 부록이 붙고 보유/활성 미체결에는 붙지 않는지 검사한다.
- 기존 경제적 거절/배분·TP·SL·권한 테스트와 전체 BTC 오프라인 회귀를 실행한다.
- 위 실제 OPEN 4개와 기존 단일 인과 시계열로 만든 synthetic aligned LONG/SHORT
  2개를 고정한다. 같은 입력으로 기준/후보를 번갈아 비교한다. 최대 24회 호출,
  재시도·주문 없음. 원응답·요청·검산·선택을 보존하고 추가 호출 없이 정확 재생한다.
- 모델 테스트는 논리/계약 진단이지 수익성 실험이 아니다. 실제 사례는 개발 표본이고
  합성 사례는 실제 매매 수로 세지 않는다. 모델 선택을 거래 실행 권한으로 취급하지 않는다.
- 최종 HEAD CI·서버 clean/ff-only·운영 Python 검증·다음 자연 실행을 각각 확인한다.
  구현·테스트·CI·배포·첫 실행·수익 개선 상태를 섞지 않는다.

상태: 구현 및 검증 대상. 배포 영수증과 첫 실행은 별도 보고하며 M5는 미입증이다.

## 1차 진단과 근거 인용 교정

6쌍의 1차 진단은 실제 18호출로 종료했다. 후보 6건은 출력 규격을 통과했지만,
최근 손실 후보의 recovery.reason 한 문장에 15분 간격 확대를 30분에도 확대라고
옮겨 쓴 오독이 있었다. 최종 선택 설명은 30분 수렴을 인정했다. 따라서 정확한
시간프레임·확정/진행 구분과 공급된 gap.state/transition을 직접 사용하도록 보완한다.
이는 무조건 WAIT로 출력을 맞추기 위한 수정이 아니다.

기준 전략의 합성 SHORT는 조건부 주문 만료 오류로 실패했고 그대로 보존한다.
따라서 1차 진단 전체를 오류 없는 A/B 또는 경제적 비교로 주장하지 않는다.
1차 HEAD의 전체 회귀는 수정 전에 종료(-15)했으며 통과로 세지 않는다.

교정 v2는 같은 고정 6개 입력에 후보만 한 번씩, 최대 12회 호출·재시도 없이
검사한다. 기준 응답을 재사용해 새로운 A/B 개선 숫자를 만들지 않는다. 목적은
근거 인용의 오류/반복 여부와 출력 계약·정확 재생 확인이다. 기존 결과·실패를
지우지 않으며, 교정 이후 최종 HEAD에서 전체 회귀·CI를 다시 수행한다.
