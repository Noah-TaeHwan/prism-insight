# M0 후속: 제한 관리의 최종 검증 지연

## 실관측과 범위

PR #1116을 12:02:48 KST 배포하고 관리 승인 1건을 등록했다. 원 UNKNOWN/선행 PENDING·신규진입 차단은 보존됐다.
관리자 사후 확인 도구가 broker 문맥에 없는 runtime 전용 `unknown_intents` 필드를 참조해 KeyError를 냈다. 등록 자체는 저장됐음을 읽기 전용으로 확인했고 중복 등록하지 않았다. 실행했던 도구 원본과 실패 기록은 보존했으며 확인 코드는 수정했다.

12:05 정기 slot 5976325에서 모델은 DRAFT 20.226초·SELECT 4.842초로 정상 완료했고 EXIT를 선택했다. 실제 주문은 생성되지 않았다.
리뷰 첫 clock부터 tape 완료까지 25.687초, 이후 첫 fresh 검증까지 30.733초, 최종 차단 보고까지 21.213초가 추가됐다.
전체 약 77.633초로 기존 75초 최종 마감을 넘었다. 입력 시세 나이 약 83초와 구분한다. 개별 GET 지연은 없으므로 추가 시간 전부를 특정 함수에 귀속하지 않는다.

코드상 일반 reconcile과 각 broker.context/active_receipt가 같은 확정 terminal 주문들을 반복 조회하는 경로를 확인했다.

## 수정 전에 고정한 최소 계획

1. 일반 `_query_child`가 실제 정확한 주문·누적 체결 대조에 성공한 TERMINAL 전체 행/증거 fingerprint를 같은 broker 객체 안에만 기억한다. 계정·endpoint를 함께 결박한다.
2. 관리 격리의 `refresh_known`에서만 현재 행이 이 fingerprint와 완전히 같으면 중복 GET을 생략한다. DB의 TERMINAL 문자열만으로 신뢰하지 않는다.
3. 재시작·broker 교체·계정/endpoint 변화·행/증거/요청 변경·확인 기록 부재는 기존 exact 조회를 수행하거나 차단한다. 지속 캐시·TTL은 추가하지 않는다.
4. 일반 reconcile과 `_query_child` 자체의 원격 검증은 줄이지 않는다. LIVE native SL·원 UNKNOWN·현재 계정 방향/잔량·외부 주문·Full SL·10초 신선도는 기존대로 확인한다.
5. 최초 승인 등록의 전체 exact 조회, 75초 마감, 입력 시각·만료, 권한 범위, 원 UNKNOWN·정산·신규진입 차단은 바꾸지 않는다.

## 검증과 완료 기준

- 실제 broker/fake exchange에서 같은 객체의 반복 관리 문맥만 terminal 재조회가 0회가 되는지, LIVE와 계정 조회는 유지되는지 검사한다.
- 새 broker와 변조된 증거·요청·상태·주문 ID·계정에서는 재사용하지 않는지 검사한다.
- 원 UNKNOWN 재전송·재취소 0회와 단일 HTTP EXIT, LONG/SHORT·FAILED·철회·만료·정산 보존 회귀를 유지한다.
- 가짜 GET 지연을 넣은 실제 검산/선택 runtime 경로로 절감과 75초 마감 보존을 확인한다. 모형의 초 단위 절감은 실제 서버 성능 보장이 아니다.
- 정확한 최종 전체 테스트·CI·독립 검토 후 별도 PR로 배포한다. 이미 등록된 동일 관리 권한은 재등록하지 않는다.
- 다음 실제 정기 판단의 모델 구간과 호스트 후처리·결과·보호를 확인하기 전에는 관리 재개 완료라고 하지 않는다. 전략 실험은 그때까지 실행하지 않는다.

## 구현과 추가 관측

제품 변경은 두 파일의 18줄 추가·2줄 삭제다. broker 객체 내 메모리 fingerprint만 사용하며, 원격 조회를 시도하면 이전 fingerprint를 먼저 무효화한다. 원격 검증과 DB 저장이 성공한 non-native TERMINAL만 기억한다. native는 TERMINAL이어도 재조회한다.

최종 관련 563개가 실제 SDK 환경에서 통과했고 네트워크 시도는 0회다. 신규 15개 회귀는 재시작·UID/endpoint·전체 행/증거 변경·최근 조회 실패·최초 등록·일반 reconcile 보존을 포함한다.
실제 2단계 runtime에 DRAFT 20초/SELECT 5초·exact 조회당 1초를 넣은 합성 지연 시험에서 기존 중복 경로는 93초로 차단됐고, 새 경로는 WAIT 69초·EXIT 73초로 완료됐다. 실제 서버 절감 수치로 보고하지 않는다.

추가 실관측으로 12:10 제한 WAIT가 정상 완료됐다. 12:15에는 별도 정기 EXIT가 한 번 제출됐으며, 후속 대조에서 0.001 BTC@80957.3 Filled·무포지션을 확인했다. 원 UNKNOWN·전체 정산·신규진입 차단은 그대로다. 이 체결은 본 성능 수리 배포 전 결과이며, 본 패치 효과로 귀속하지 않는다.
