# JSON 출력 형식 후보: 성능 기준 미달, 미배포

기준 `cf6fe78a`와 후보 `9cf6bfac`를 개발 입력 4개에서 각각 3회 비교했다. 후보는 DRAFT_PROMPT에 JSON을 공백 없이 출력하도록 요청한 한 문장뿐이다. 스키마·판단 내용 한도·위험·모델·SELECT는 유지했다. 실제 실행 순서는 사전 등록한 AB/BA 목록과 일치했다. 44 HTTP로 24개 실행을 완료하고 장부를 봉인했다. 실주문은 없고 남은 4회는 재개하지 않는다.

후보의 모든 DRAFT에서 문자열 바깥 서식 공백은 0이었다. 그러나 사전에 정한 비교 조건(동일 단계 수, 후보 행동과 배열 개수, 비서식 문자 수 차이 10% 이하)을 만족한 주 비교 8쌍의 시간 절감 중앙값은 **2.0966초**로 기준 3초에 못 미쳤다. 입력별 중앙값은 F01 +1.5871초, F02 −1.3859초, H01 +2.6061초였다. 이미 공백이 적었던 대조 입력 H02는 3회 중 1쌍만 비교 가능했다.

판정은 `NO_REGISTERED_PERFORMANCE_PASS`다. 기준안도 일부 응답은 처음부터 공백이 없었고, 선택 행동·단계 수·API 입력 캐시량이 달라진 쌍도 있었다. 빠른 응답만 골라 형식의 효과로 계산하지 않았다. 기준을 낮추거나 같은 실험을 추가 호출하지 않으며 이 후보는 배포하지 않는다.

관련 검사 71개와 실행 중 기술 검증이 통과한 사실은 성능 기준 통과를 뜻하지 않는다. 이 실험은 과거 판단 입력을 고정한 주문 없는 비교이며 운영 계좌 재조회나 전략 수익을 검증하지 않았다. 같은 입력의 반복을 독립 거래로 세지 않는다.
