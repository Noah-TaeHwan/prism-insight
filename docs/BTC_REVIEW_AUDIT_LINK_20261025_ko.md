# M3 검토 이력 연결 수리

## 범위와 수리 전 기준

오늘 감사에서 WAIT 재승인 4건과 설명 표시 변환 뒤 보유 판단 12건의 감사 연결 누락이 확인됐다. 주문 실패 건수와 다르다. 원문·검증 후 payload·intent·검토 영수증을 각각 정확히 연결하되, 매매/보호/정산 규칙은 바꾸지 않는다.

최소 변경 계획: 이미 저장하는 proposal JSON을 감사 함수에도 전달한다. WAIT의 pending_renewal도 intent를 필요로 하는 행동으로 분류한다. 별도 원문 복원/추정/과거 원장 덮어쓰기는 하지 않는다. 기존 미사용 valid_record import 한 줄만 제거하고 그 외 정리는 하지 않는다.

## 검증

실제 runtime과 가짜 모델·거래소를 사용해 WAIT/ADJUST/EXIT/REDUCE의 설명 변환 및 LONG/SHORT 재승인 6개를 재현했다. 제품 수정 전 모두 감사 연결 실패, 이후 정확한 연결과 변조·intent 누락 거부를 검사한다. 저장 설명은 짧은 해석 문자열이며 검증 후 공식 표시문과 다르다. 최초 테스트 작성 중 런타임 메서드를 교체하면 소스 무결성 검사가 막는 것을 확인해, 실제 메서드는 그대로 두고 기존 run_capture로 검증한다.

이 수리는 앞으로 생성될 감사 이력만 개선한다. 과거 누락된 전후 body는 만들지 않으며 원 UNKNOWN·정산 부재·신규 진입 차단도 해소하지 않는다. 기존 이력/검토 메모/거래소 증거/주문 권한은 그대로다. 배포와 첫 자연 실행은 별도 확인한다.
