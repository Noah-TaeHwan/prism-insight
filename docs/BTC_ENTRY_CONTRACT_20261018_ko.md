# 최초 진입 전제와 실패 집행 계약 v1

사용자 승인: 진입 이유에 맞는 상황을 벗어나면 정리하고, 보유 중 다른 전략으로
재해석하지 않는다. 범위는 M0/M3/M4이며 수익 보장·M5 승격이 아니다.

## 구현 전 기준

- 최초 OPEN의 작은 entry_contract를 action/input/scenario ID에 묶어 active에 불변 보존한다.
- regime은 TREND/BREAKOUT/RANGE. MA 사이 위치만으로 RANGE를 추정하지 않는다.
- premise/expected_progress는 각각 최대 240자로 최초 진입 전제를 보유 판단에 연결한다.
  현재 시장의 사실이나 별도의 숫자 집행 조건으로 취급하지 않는다.
- explicit_failure는 MARK_PRICE의 ge/le 가격과 minimum_observations 2 또는 3이다.
  모델이 실패 가격·확인 횟수를 정한다. SHORT는 진입보다 높은 ge, LONG은 낮은 le이며
  최초 SL보다 손실 쪽으로 멀어질 수 없다. 활성화 트리거와 별개다.
- 서로 다른 연속 5분 decision slot의 신선한 실제 계좌 관측만 센다. 중복·과거·미래·
  오래된 자료는 증거가 아니다. 슬롯 누락/가격 회복이면 확인 누적을 다시 시작한다.
  관측 사이에도 가격이 계속 유지됐다고 주장하지 않는다. 최초 확인 체결 이후부터 평가한다.
- 확인된 수치 실패는 latch로 보존하고 LLM 호출 없이 기존 cancellation-first EXIT 경로로
  처리한다. 미확정 주문·체결을 건너뛰거나 중복 청산하지 않는다. 1분 기존 보호는 그대로다.
- 모델의 정성 판단은 thesis_assessment(contract_id,status,reason)로 남긴다.
  INTACT/WEAKENING/FAILED/UNKNOWN을 구분한다. FAILED를 유효하게 선택하면 EXIT만 허용한다.
  이는 모델 판단이며 호스트가 정성적 시장 진실을 증명한 것은 아니다.
- 계산 분리 DRAFT의 WAIT template와 모든 후보는 동일 assessment를 사용한다.
  FAILED WAIT는 비실행 template로만 남고 선택 대상에서 제외된다. 유효한 EXIT 후보가
  없거나 응답이 잘못되면 부분 문자열만 보고 청산하지 않고 오류/UNKNOWN으로 처리한다.
- ADJUST/추가진입/재시작은 최초 계약을 교체하지 않는다. 새 전략은 전량 종료·정산 뒤
  별도 시나리오로만 시작한다. 기존 활성 거래는 LEGACY_UNKNOWN이며 사후 계약을 만들지 않는다.
- 잘못된 계약/자료 누락을 성공·실패로 채우지 않는다. 기존 Full SL·보호와 안전한 EXIT를 유지한다.

최초 계약은 active의 자기 해시뿐 아니라 INSERT-only 원본 등록과 대조한다.
정성 FAILED와 EXIT intent도 별도 원본에 묶어 보존한다. 청산 주문의 terminal은
포지션이 비었다는 뜻으로 취급하지 않는다. 확정 거절·취소 후 잔량이 남으면
`entry_contract_failed_exit_unresolved`로 차단·경보하며 새 전략 WAIT로 복귀하거나
미확정 주문을 재전송하지 않는다. 현재 계좌가 불확실해도 과거의 유효한 실패는 해제하지 않는다.

기존 계약 없는 활성 거래와 손상 계약은 신규 증액을 차단하지만 기존 보호·EXIT는 유지한다.
숫자 실패는 최초 확인 체결 이후부터 평가하므로 무체결 대기 주문은 기존 만료 취소 또는
유효한 모델 FAILED→EXIT 취소 경로를 사용한다. 기존 계약은 신규 생성 옵션을 꺼도 유지한다.

## 변경 범위

작은 계약 모듈, version-gated wire, 계산/선택/최신 상태 guard, runtime 저장·수치실패
청산, 프롬프트·manifest·회귀 테스트를 연결한다. 신규 지표·서비스·스케줄·모델·위험 예산
변경은 없다. opt-in 기본 OFF로 구현해 옛 재생/활성 거래를 보호하고 운영 활성화는 검증 후 결정한다.

## 수락 테스트

롱/숏, 순간 touch/정상 재시험, 독립 연속 관측, 공백·중복·미래·오래된 관측,
무체결/부분체결/대기 주문, 실패 중 통신 오류·재시작·중복 의도, 계약 바꿔치기,
모델 호출 중 새 실패 확인, 실패 WAIT/ADJUST 선택 거절과 실제 EXIT intent,
legacy 보호, 최초 OPEN과 원자적 계약 저장·정확 재생·입력 용량을 검사한다.
실제 주문으로 검증하지 않는다. 합성 케이스는 거래 성과 표본이 아니다.

불변 계약 전달과 실패 집행은 검증하되, 초기 실패 가격의 적절성·모델의 정성 판별 정확성·
수익 개선은 별도다. 일반 메모를 청산 권한으로 바꾸거나 테스트 통과를 수익 증명으로 쓰지 않는다.

## 고정 프로토콜 모델 진단

실제 보존 무포지션 SHORT 입력 1건, 기존 합성 무포지션 LONG 1건, 보존 가격 입력에
가상의 등록 계약을 부여한 SHORT 보유 2건, 합성 LONG 보유 1건, 계약 없는 실제 보존
보유 1건을 고정한다. 가상 계약은 당시 실제 계약을 복구한 것이 아니라 명시적인
프로토콜 fixture다. 수익 비교·매매 판단 우열에 사용하지 않는다.
최대 12회 OAuth 호출, 재시도·주문 없음. 양 단계 계약 보존, 응답 규격, 선택과 실패 평가의
일치, 정확 재생을 검사한다. 실제 모델이 FAILED를 선택하지 않은 경우 해당 실제 판단
사례가 없다는 점을 남기며, 결정론 모의 통합의 실패→EXIT 검증과 구분한다.

1차 실제 진단은 8호출로 6건 모두 형식·재생을 통과했지만, 한 후보가 자유서술
failure_basis에는 83600, explicit_failure에는 83800을 써 두 기준이 생겼다.
배포 전에 별도의 failure_basis 필드를 제거하고 숫자 규칙을 단일화했다.
호스트는 등록된 explicit_failure에서만 entry_contract_failure_rule을 생성한다.
옛 중복 필드 입력은 거절한다. 일반 설명의 모든 의미 오류를 자동 검증한다는 뜻은 아니다.
1차 전체 테스트는 소스 수정 전에 -15로 중단했으며 통과로 세지 않는다.
교정된 같은 6개 프로토콜 입력에 최대 12회·재시도 없는 v2 진단을 별도로 등록한다.
구체적 사례를 보고 바꾼 개발 교정이며 독립 검증이나 새 A/B 성과 비교가 아니다.
