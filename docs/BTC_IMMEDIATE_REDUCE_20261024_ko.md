# 즉시 일부 감축 — Stage B (M0/M3/M4)

## 계약

사용자 승인된 새 실행 선택지이며 부분손절 의무화나 수익성 검증 결과가 아니다.
호스트가 `immediate_reduce_version=1`을 제공하고 현재 감축을 허용할 때만 모델은
`REDUCE`와 `0 < reduce_fraction < 1`을 제안할 수 있다. 수량·방향·가격·새 목표를
모델이 지정하지 않는다. 기존 계약을 재작성하지 않으며 버전 없는 기존 입력은 종전대로다.

확정 보유·보호·회계와 신선한 수량이 필요하다. 미체결 진입·미확정 주문·타 노출·FAILED
상태는 새 REDUCE 근거가 아니다. FAILED는 기존 전량 EXIT를 우선한다.

## 수량·주문·보호

호스트는 원 수량 Q0에서 step 내림한 감축량 D0와 목표 잔량 R0를 고정한다.
감축량과 잔량의 최소수량, 시장 주문 상한을 검증하며 자동 분할이나 위험 추가는 없다.
intent와 같은 DB 트랜잭션에서 원 Full SL과 소유한 TP/부분SL의 미체결 quota를 보존한다.

기존 TP/부분SL 취소·체결을 대조한 뒤, 이미 줄어든 수량을 포함해 목표 잔량까지 필요한
양만 reduce-only 시장가 IOC로 한 번 제출한다. native Full SL은 취소하지 않는다.
응답 유실은 고정 ID로 조회하며 새 POST를 반복하지 않는다. 부분체결 뒤 자동 보충도 없다.

확정 잔량의 TP/부분SL은 미체결 quota에서 비례 축소·step 내림해 복원한다. 이미 체결된
목표를 되살리지 않고, 복원 과정의 추가 체결도 최신 잔량으로 대조한다. 내림 잔량은
Full SL로 보호한다. 기존 current_plan·원 계약·위험 예산을 빈 REDUCE 필드로 덮어쓰지 않는다.

## 실패를 성공으로 보고하지 않는다

- COMPLETE: 감축과 필요한 잔량 보호 복원이 확인됐다.
- RESTORE_FAILED: 복원 주문의 거절·미체결 취소가 확정됐다. 성공 완료가 아니다.
  실패 출처를 보존하고 같은 intent를 재전송하지 않는다. native SL은 유지하며
  새 REDUCE는 제한하고 ADJUST/EXIT를 통한 관리는 허용한다.
- SKIPPED_FAILED: 전제 실패 후 신규 감축·복원 POST를 추가하지 않고 기존 전량 EXIT로
  넘긴다. 이미 미확정으로 제출된 주문은 먼저 정확히 대조한다.
- 만료: 새 감축 제출은 하지 않되 필요한 보호 복구와 대조는 진행한다.

정상 ACK 후 확인 대기와 전송 불명확을 구분한다. 이 구분은 체결 완료나 재전송 허가가 아니다.
새 `reduce` 체결 종류와 durable 상태는 재생 해시·정산·관측 도구에도 그대로 기록한다.

## 검증·롤아웃

LONG/SHORT, 최소수량·내림·잔량·상한, TP/SL 경합, 부분체결, 응답 유실·재시작,
중복 호출, 복원 실패, FAILED, 만료, 위조, 잔량 보호를 실제 모듈과 가상 거래소로 검사한다.
새 테이블의 모든 상태를 재생 해시에 포함하며, 신규 기능을 안 쓴 기존 재생도 확인한다.
모델 schema→후보 계산→fresh guard→원자 저장→집행→부분 회계의 연결 검증이 필요하다.

Stage A와 별도 PR/근거로 검증·배포한다. 배포 후 실제 자연 감축이 없으면 미관측으로
보고하며 수동 주문으로 표본을 만들지 않는다. 미완료 REDUCE가 존재하면 이를 모르는
구버전 실행기로 단순 롤백하지 않는다. 신규 제안 비노출과 기존 intent 대조를 분리한
안전한 roll-forward를 우선하며, 모든 상태가 정산된 뒤에만 구버전 복귀를 검토한다.
