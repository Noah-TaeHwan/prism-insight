# 진입·보유 판단과 직전 청산 맥락 (Stage A, M0/M3/M4)

## 승인·범위

사용자는 2026-10-24 세 손절 복기 뒤 최종 개선안 전부의 구현·데모 배포를 승인했다.
기준선은 e826638a이다. 이 단계는 판단 입력과 지침만 바꾸며 즉시 일부 감축의 새 실행
명령은 별도 Stage B로 둔다. 수익성 M5 통과 또는 실자금 승격으로 해석하지 않는다.

## 작동 가설과 보존 조건

약한 MA 교차와 실제 가격 진전·목표 전 장애를 구분하고, 반대 방향 재진입에 독립적인
근거를 요구한다. 위험 한도·소규모라는 사실은 진입 우위가 아니다. 보유 중에도
‘아직 실패하지 않음’과 현재 수량을 유지할 우위를 구분한다. 기존 비용 경로를 같은
가정끼리 비교하되 UNKNOWN을 확정 비용으로 바꾸지 않는다.

강한 돌파를 확정봉/재시험 대기로 무조건 막지 않고, MA10→MA35 구간 거래를 보존한다.
새 교차폭·손절횟수·시간 벌점이나 부분손절 의무화는 없다. 최소30분 분석, 1시간 우선,
15분 보조 금지, 위험·일 손실·보호·FAILED 전량 EXIT 규칙은 그대로다.

## 실제 전달 경계

- `scenario_position_flow.build_closed_continuity`: 완료 원장의 마지막 확정 체결 거래 한 건을
  정산·감사·원계약·OPEN intent에 연결한다. 최근288개 판단 범위에서 같은 EXIT의 원문과
  실행 payload가 정규화 후 일치할 때만 당시 평가를 역사적 의견으로 붙인다.
- `scenario_runtime`: 이 결과를 frozen context의 `last_closed_trade`에 넣는다.
- `scenario_llm`: 기존 진입·보유 문단에서 위 비교를 수행한다. 새로운 실행 권한은 없다.
- 모델 입력: 기존 보유 이력 선택을 먼저 유지한 뒤 선택적 청산 맥락을 추가한다. 3KB 또는
  전체100KB를 넘으면 명시적으로 생략하며 원 시장·위험 자료를 잘라내지 않는다.
- 원계약·평가 사유·원문 해시는 유지하고, 같은 EXIT의 긴 rationale 중복 사본은 보내지 않는다.
  원본은 DB에 남는다. 실제 체결 시각은 근거가 없으면 UNKNOWN, 감사 시각은 정산 관측 시각이다.

## 검증·반증

정상 LONG/SHORT와 누락·미래 시각·다른 시나리오·감사 불일치·실행 필드 변조·손상·크기
경계를 검사한다. 실제 최신 반대 진입 사례에서도 맥락이 들어가는지 검증한다.
세 손실은 개발 회귀이며, 확정 승리 LONG/SHORT와 보유·예약 원자료를 함께 고정해
주문 없는 모델 선택을 검사한다. 과거 결과를 입력에 새로 유출하지 않는다.

진입 감소 자체는 성공 기준이 아니다. 강한 추세·정상 반전의 과도한 배제, 근거 없는
감축, 현재 사실과 과거 의견의 혼동은 반증이다. 수익·손실·비용·큰 수익 보존은 별도
후속 평가이며, 부족한 표본으로 수익 개선을 선언하지 않는다.

## 배포·복귀

전체 회귀·독립 검토·정확한 head CI·서버 검증·고정 native 요청을 확인한 뒤 데모에
단계별 배포한다. 새 cron/계정/강제 주문은 만들지 않는다. A는 새 주문 action을 만들지
않으며, 불필요한 생략·왜곡·시간/입력 한도 문제가 드러나면 해당 변경만 복귀한다.
배포 후 자연 판단·보호 관측을 코드 완료와 별도로 기록한다.
