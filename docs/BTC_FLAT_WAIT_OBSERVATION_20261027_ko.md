# 무포지션 관망의 중복 계좌 조회 보완

대상: M0 실행 안정성. 수익 전략·위험 한도·판단 기한은 변경하지 않는다.

최근 시간초과 9건 중 8건의 저장 입력과 선택은 active/holding/pending/unknown/cancel/renewal이 없는 WAIT였다. 첫 모델 후 재조회와 검증을 완료한 뒤 같은 잠금 안에서 다시 reconcile/context를 실행한다. 후자의 네트워크 지연은 75초 최종 기한에도 포함된다. 근거는 `tasks/btc-review-latency-20261026/`에 보존한다.

실제 broker가 무포지션·무주문을 확인한 계좌 버전과 모델 후 context의 버전이 같을 때만 그 context를 최종 순수 검증에 재사용한다. WAIT·active 없음·unknown 명시적 false·빈 포지션/대기/목표·정산 확인·신규 위험 차단 없음·격리 없음·취소/갱신/permit 없음이 모두 필요하다. 계좌 캡처 시각은 바꾸지 않고 재사용 전후 10초를 검사한다. 첫 모델 후 정합·보호·진입계약 점검, 두 번의 순수 guard, 소스 일치·75초·입력 유효기간 검사는 유지한다. 증거가 부족하거나 주문 권한이 있는 경로는 기존 마지막 조회를 유지한다.

영향 범위: `scenario_runtime._reconcile`의 반환값을 post-model 호출 한 곳에서만 소비한다. 초기 호출·재생·기존 테스트 호출자는 반환값을 무시한다. broker/API/설정/프롬프트/위험 예산은 그대로다. `test_flat_wait_observation.py`가 실제 runtime과 review adapter로 경계와 조회 횟수를 검사한다.

검증 구분: 로컬 관련 테스트 진행 중. 전체 PR CI·배포·첫 정기 실행·2단계 WAIT 시간초과 감소·24시간 무경보·M5 수익성은 아직 미입증이다. 외부 거래소 상태가 캡처 직후 달라질 수 있는 기존 한계는 남지만 이 경로는 주문 권한을 만들지 않는다. 관망에서 발견되는 외부 상태 변화의 재확인은 다음 보호/정기 점검에 의존할 수 있다.
