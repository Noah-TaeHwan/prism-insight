# M0.3 전송 전 차단이 UNKNOWN으로 남는 결함

## 사건 및 재현

2026-10-26 01:15 경보는 기존 격리 주문이 아니라 새 시나리오
`s_55d333c6722dba9c167c4c34`의 진입 `sc_b7cafdb91c0d43da95926732c1a850b4`다.
운영 소스는 `53931d3225fe0b6b9ad123cb999561f1183d7ce7`이다.

- 격리 감시 시작: 1792941356.810초. 관측 유효기간은 시작부터 10초다.
- 첫 전송 가드 뒤 SENDING 기록: 1792941366.7135055초.
- 최종 가드 앞 EXCHANGE_REQUEST 기록: 1792941366.8696초.
- EXCHANGE_ERROR(submission_unknown): 1792941366.8843553초.
- 반환 기록: 1792941366.8852043초.

벽시계가 역행하지 않았다는 조건에서 첫 가드는 통과하고 최종 가드에서 만료된다.
기존 소스는 HTTP를 호출하기 전에 이 예외를 submission_unknown으로 바꾼다.
그보다 먼저 child UNKNOWN을 확정 저장하므로 새 매매가 영구 보류된다.
실제 가드를 사용한 지연 테스트와 첫/최종 가드 거절 테스트로 결함을 재현했다.
거래소의 정확한 주문 ID 조회 3종은 빈 결과였으나 이것을 미접수 확정 증거로 삼지 않는다.
과거 사건에 예외의 원종류·attempted 값이 기록되지 않은 한계는 남는다.

## 최소 수리

진입 child는 선행 로컬 검사 통과 뒤 저장하며, DB commit 뒤에도 최종 가드를 다시 검사한다.
commit 지연으로 이 마지막 가드가 실패하면 이번 호출에서 SDK 전송을 하지 않았음을 아는 범위에서만
원 child 전체를 append-only 증거로 보존하고, ABORTED 배치 확정과 활성 child 제거를 원자적으로 수행한다.
증거 저장/원자 처리에 실패하면 UNKNOWN을 남겨 차단한다. 과거 기록에는 이 처리를 적용하지 않는다.
기존 청산·손절 복원의 선행 UNKNOWN 저장은 유지한다.
DB commit은 SDK보다 먼저 끝나므로 실제 전송 뒤 timeout이나 프로세스 종료는 계속 UNKNOWN으로
보존하고 재주문하지 않는다. 전송 전 실패는 기존 ABORTED 배치의 미전송 처리로 정리한다.
기존 UNKNOWN을 삭제하거나 거래소 Rejected/Cancelled로 소급 표시하지 않는다.

수정 범위: 실행 mixin, 전송·격리·손절 복원 회귀. 호출자 인터페이스는 내부 callback만 추가한다.
전략·위험한도·보호 가격·계좌 자격증명은 변경하지 않는다.

## 검증 및 남은 단계

- 수정 전 신규 경계 검사 2개가 UNKNOWN 잔존으로 실패했고, 응답 유실 보호 검사는 통과했다.
- 실행/격리 207개 검사 통과. 추가 실제 가드 지연·손절 복원 검사는 104개 통과, SDK 미설치로 3개 skip이다.
  즉시감축 검사도 통과했다. 재실행 겹침을 합산해 고유 검사 수로 보고하지 않는다.
- PR CI·배포·기존 UNKNOWN 해제·첫 정기 실행·새 24시간 무경보는 아직 완료하지 않았다.
- 10/25 전환 이후 24시간 무경보 목표는 이번 경보로 미충족이다. 이전 경보를 지워 새 성공으로 세지 않는다.

전체 CI에서 격리 청산의 사전 재시도 설정 실패 경계가 깨져, 변경 대상을 진입으로 한정했다.
청산 UNKNOWN 계약을 완화하거나 해당 검사를 바꾸지 않는다. 새 head에서 CI를 다시 확인한다.

범위를 진입으로 한정한 뒤 실행·격리 청산·손절 복원 189개 통과, SDK 관련 6개 skip이다.

DB commit 지연을 주입한 반례로 마지막 가드의 위치도 검증했다. 운영과 같은 pybit 5.16.0을
저장소 밖 임시 경로에 준비해 앞서 skip됐던 실제 SDK 단일 전송 경계 6개가 모두 통과했다.
프로젝트 의존성이나 운영 환경은 변경하지 않았다.

최종 가드/미전송 원본 보존 경로를 포함한 관련 275개 검사가 pybit 5.16.0 환경에서 통과했다.
추가로 증거 저장 실패·기존 COMPLETE 배치·재시도 차단 조합 4개가 통과했다.
원 child 제거는 같은 호출에서 아직 SDK를 부르지 않았을 때만 수행하며, 실패 시 UNKNOWN을 보존한다.
이번 00:16 주문에는 이 전향적 증거가 없으므로 소급 적용하지 않았다.
