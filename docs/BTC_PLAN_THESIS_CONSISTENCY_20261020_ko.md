# BTC 목표·원래 가설 정합성 수리

## 구현 전 검토 6항

1. **유형·범위:** M3/M4 판단 설명 오류 수리다. 기준선은
   `9d4a1466554bbbeb7b769fe03b2a2cfe1f0ac798`이다. 13:05 보존 사례의
   LONG 82,300 진입·82,900 TP(유효 82,892.7)는 “일봉 MA35
   82,806.19 아래”라는 원래 설명 및 expected_progress와 맞지 않는다.
   수치 계산 결함은 아니며 확정/형성 혼동은 원인 가설일 뿐이다.
2. **작동 이유·반증:** 모델이 TP별 인용 기준과 원래 가설을 함께 대조하도록 한다.
   SELECT가 설명만 고쳐 모순을 감추거나 단순 MA 자동 상한으로 해석하면 실패다.
   함께 제안했던 MA10→MA35 독립 검토 흔적 보완은 아래 실제 반례로 제외했다.
   강제 후보·확률·새 탐지기는 추가하지 않는다.
3. **연결·충돌:** 공유 MA 지침 → DRAFT → 기존 host 계산 → SELECT 순서다.
   raw 계약·rationale와 유효 계획은 모두 불변이다. 일관된 돌파 지속 가설은 허용하며,
   기존 bounded gap 규칙은 그대로 두며 이번에 변경하지 않는다. 기존 보유를 강제 EXIT하지 않는다.
   수량·위험·보호·예약 갱신·주문·스키마·입력 데이터는 바꾸지 않는다.
4. **사전 검증 기준:** LONG/SHORT, 확정/형성, 일부 TP만 기준을 넘는 경우,
   근거 있는 돌파 연장을 검증한다.
   실제 DRAFT/SELECT 요청의 지침 전달 및 입력·계약·receipt 복원을 확인한다.
   오프라인 회귀는 모델 해석 능력의 증거가 아니다. 부모가 보존 입력으로 한정된
   실제 비교를 수행하며 재시도·주문·수익 추론은 하지 않는다.
5. **원인 분리·복귀:** 프롬프트 전달, host 정합성, 실제 모델의 설명/선택을 분리한다.
   판단을 임의로 차단하거나 보호를 바꾸는 회귀는 배포하지 않는다. 일반 정확도와
   수익성은 미입증이며 첫 자연 실행을 별도 확인한다. 추가 연구는 자동 시작하지 않는다.
6. **현재 결론:** 승인된 좁은 판단 지침 수리를 구현·검증한다. 새 SHADOW/LIVE
   승격이 아니다. 구현/전체 테스트/CI/배포/전진 관측은 각각 확인 후 기록한다.

## 파일 계획

- `live/scenario_llm.py`: 공유 TP·인용 기준·원래 가설 대조 규칙.
- `live/scenario_calculated_review.py`: DRAFT 공통 정합성 검사와 SELECT 불변 계약 검토.
- 관련 테스트: 실제 요청 조립, 대칭 반례, 기존 receipt/입력/계약 보존, 프롬프트 핀.
- 새 metadata·계산·자동 MA 상한·정규식 출력 차단·추가 모델 호출은 없다.

## 실제 비교 후 범위 축소

부모가 보존한 8회 진단에서 13:05 후보의 SELECT는 원래 가설/TP 불일치를
명시하고 WAIT를 선택했다. 그러나 gap 보완은 12:35의 실제 1h 경로를 관측되지
않았다고 설명했고, 12:10도 경제 검산 없이 좁은 공간을 사유로 후보를 내지 않았다.
따라서 gap 보완은 검증 통과가 아니며 추가 DRAFT/SELECT 문장과 해당 테스트를
이번 PR에서 제외한다. 실패 원문과 첫 후보 커밋은 보존한다.
최종 범위는 TP·인용 기준·원래 가설의 정합성뿐이다. 좁힌 최종 버전의 실제
SELECT 검증은 부모가 별도 등록한다. gap의 인식/채택 문제와 일반 정확도·수익성은
미해결이며 테스트 성공을 그 해결로 해석하지 않는다.
