# BTC OAuth 응답 전송 중단 복구

## 사건과 범위

2026-10-12 12:55 KST 슬롯5972591에서 MODEL_REQUEST 후 약11.44초 만에 oauth_model_failed가
기록됐다. 같은 시각 프록시 로그는 응답 본문의 TransferEncodingError(전송 길이 미충족)를 기록했다.
75초 지연 응답이나 전략의 출력 규격 거절로 확인된 사건이 아니다. 다음13:00 판단은 WAIT로 자연 복구했고,
저장된 보호 관측도 protection_checked·verified_flat이었다. 이 확인은 거래소 직접 조회와 구분한다.

M0 실행 안정성·M3 실패 기록 보완이다. 전략·프롬프트·모델·위험·주문·스케줄·공용 프록시는 변경하지 않는다.

## 좁은 복구 계약

1. 현재 localhost OAuth 프록시의 확인된502 응답 본문 중 해당 전송 중단만 판별한다.
2. 운영 runner가 명시적으로 허용한 경우에만 같은 요청을 최대 한 번 추가 전송한다. 도구 호출·원격 URL·다른 인증 경로는 금지한다.
3. 최초 호출의75초 수용 기한을 공유하고 남은 timeout만 사용한다. 늦은 결과는 주문으로 적용하지 않는다.
   urllib의 socket timeout이 강제 총 실행시간 제한이라고 주장하지 않는다.
4. 인증 오류·429·명시적 terminal error·다른502·JSON/SSE/규격·모델 불일치에는 적용하지 않는다.
5. 실제 HTTP 시도는 같은 슬롯/input_id에 안전한 종류·시간·횟수로 기록한다. 오류 원문·응답 본문·인증값은 남기지 않는다.
   첫 시도의 기록이 실패하면 추가 시도는 하지 않되, 성공한 첫 응답을 알림/기록 실패만으로 실패 처리하지 않는다.
6. 기본 client·주입된 연구 generator는 기존 한 번 호출을 유지한다. 동결 실험과 실제 모델 호출 상한을 몰래 바꾸지 않는다.

완전한 응답 하나를 받은 뒤 기존 규격 검사와 최신 계좌·보호·입력 재확인을 그대로 거친다.
주문 재전송이나 실패한 전략 판단을 성공할 때까지 반복하는 기능이 아니다.

## 검증·출시

실제 오류를 모사한 first-fail/second-success, 두 번 실패, 비대상 오류, 시간 소진·늦은 성공,
원본 요청 동일성, 시도 기록 실패, 운영 opt-in/연구 기본값 및 실행 안전을 격리 테스트로 검사한다.
운영에 고의 오류나 시험 주문을 만들지 않는다. CI·서버 배포·첫 자연 판단은 별도로 확인한다.
현재 서버 기준 b547b2f6과 무관한 main 변경을 함께 배포하지 않는다. 배포 범위 확인 전에는 운영을 변경하지 않는다.

## 구현 검증 기록

OAuth client·운영 runner·복구 기록 helper와 회귀 테스트를 보완했다. scenario_llm은 설명만 수정했고
기존 파서·모델 규격·실행 상태 재검사를 재사용한다. 공용 프록시와 새 의존성 변경은 없다.
관련150개, 독립 검토198개 격리 테스트를 통과했다. 중복 JSON 키로 오류 분류를 우회하는 반례도 거절한다.
전체 BTC 테스트·CI·서버 배포·첫 자연 실행은 별도 확인한다.
MODEL_TRANSPORT_ATTEMPT의 retry=true는 추가 시도 예정이며, 실제 추가 호출은 attempt=2 행으로 센다.
