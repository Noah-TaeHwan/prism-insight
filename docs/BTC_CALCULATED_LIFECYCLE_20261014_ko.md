# 계산 분리 후속: 보유·재생·실행 경계 계약

사용자의 자율 진행 승인에 따라 M0/M2/M3/M4 후속을 구현한다. 기존 v1/v2 등록 소스·응답은 수정하지 않는다. LLM은 전략 가격과 수량을 선택하고 코드는 산술과 안전 검증을 담당한다. 위험 한도·회복 허가·실자금 정책은 변경하지 않는다.

1. 보유 ADJUST/EXIT 후보를 지원한다. 확정 잔량의 손익과 미체결/신규 진입이 모두 체결되는 가정을 별도 표시한다. 기존 TP 소진량은 실제 잔량에 반영된 상태로 취급하고 다시 채우지 않는다. 취소 요청은 예약 위험을 해제하지 않는다. 회계 결측은0으로 바꾸지 않는다.
2. 두 단계 요청·응답·기록과 시계 호출을 순서대로 보존하는 테이프를 구현한다. 실패·미완료는 실패로 재생하며, 원본·순서·시간·계산·최종 선택 변조를 차단한다. 재생 성공은 경제적 수익 입증이 아니다.
3. 원래 스냅샷·입력과 완결된 테이프를 묶고, 실행 직전 최신 계좌/잔량/예약/위험 조건을 대조한다. 현재 Mark 자체가 달라졌다는 이유만으로 일괄 차단하지는 않지만, 기존 가격 보정 결과의 경제적 값이 달라지면 재검토 없이 실행하지 않는다. 원본 안을 한 번만 보정하고 보정된 안을 원본으로 재사용하지 않는다.
4. 기존 보호·브로커·회복 허가를 우회하지 않는다. 기록 중 후보 응답만 존재하는 상태는 최종 판단 완료가 아니다. 기본 운영 경로는 검증 전에 전환하지 않는다.

이 문서는 이전 flat-only 연구 계약의 후속 버전이다. 후보 계산 함수는 여전히 실행 권한이 없는 영수증을 반환한다. 명시적으로 활성화한 runtime adapter만 완결 테이프·최신 상태·기존 회복 허가를 검사한 뒤 intent로 연결할 수 있다. 기본값은 OFF이고 CLI·cron에는 활성화 경로를 추가하지 않는다.

정확한 단계별 테이프 재생과 기존 손익 시뮬레이터의 호환은 구분한다. 기존 단일 응답 경제 재생기가 다단계 기록을 잘못 짝지어 손익을 계산하지 않도록 명시적으로 거부한다. 이 변경만으로 기존 경제 백테스트가 새 경로를 지원한다고 주장하지 않는다.

수정 전 기존47개 연구 테스트를 회귀 기준으로 유지한다. 추가 검증은 롱/숏, 부분체결/부분TP 이후 잔량, 추가진입 예약·취소, 손절 복원/강화, EXIT, 회계 결측, 두 호출 성공/실패·시간초과, 테이프 변조, 계좌 변경, 실제 보정 가격 변경을 포함한다. 실제 주문을 내거나 강제 청산해 표본을 만들지 않는다. 전체 오프라인 테스트·독립 검토 이후 운영 통합 여부를 따로 판정한다.

구현 담당은 후보 계산/판단 모듈, 재생 담당은 테이프 모듈, 주 담당은 검증 경계·문서·통합을 소유한다. 코드 재사용을 우선하고 새 의존성을 추가하지 않는다. 운영 연결·배포·모델 실제 비교·수익 개선 여부를 각각 구분해 보고한다.
