# BTC 진입 전 부분익절·부분손절 결합 검토

## 범위와 승인
M3/M4. 사용자 승인: 부분익절·부분손절·잔여 물량을 진입 전에 함께 비교한다.
부분손절을 의무화하거나 숫자 손익비를 맞추려고 SL을 조이지 않는다.
확정 실패 시 기존 전량 EXIT, native SL, 원계약, 위험 예산·수량 산정·주문 권한은 불변이다.
큰 수익 가능성과 순손익 개선은 구현·테스트만으로 입증하지 않는다.

## 사전 검증 계약
1. 현재 후보 계산은 TP/부분SL별 독립 수치만 제공한다. 해당 수치를 경로 전체 이익처럼 더하지 않는다.
2. 신규 flat OPEN의 원래 계획에 한해 제한된 가상 순서의 수량·전체 총손익을 호스트가 계산해 선택 단계에 제공한다.
   기존 보유/ADJUST에는 이 최초 진입 가정을 소급하지 않는다.
3. 경로는 TP후잔량최종SL, 부분SL후잔량최종SL, 첫TP후부분SL후잔량최종SL,
   첫부분SL후TP후잔량최종SL을 비교한다. 없는다리는 생략/중복제거하되 보유량을 되살리지 않는다.
4. 가상 순서·전량신규진입가정·완전체결가정임을 명시한다. 발생 확률·예상순이익·실제체결·수익성승인으로 제시하지 않는다.
5. 기존 revision의 분할수량·step·minimum 및 원래 수량 상한을 준수한다. 단순히 매 단계 잔량에 fraction을 재곱하지 않는다.
   서로 다른 시점의 주문 갱신·부분체결 경쟁은 미모형화임을 표시한다.
6. 수수료는 기존 검증된 이력 기반 추정 도구를 재사용하며 근거가 없으면 UNKNOWN이다.
   펀딩·슬리피지·체결지연은 추정하지 않고 미모형화로 남긴다. 위험 준비금을 실수수료로 치환하지 않는다.
7. 부분손절의 계획상 손실 감소를 위험 예산 회복·물량 확대 근거로 사용하지 않는다.
8. 후보 생성은 정상 진행/약화/확정 실패를 구분하고 구조적으로 타당한 부분축소가 없으면 빈 계획을 허용한다.
   선택은 결합 경로의 보상·손실·회복 후 남는 물량을 비교하되 고정 손익비 통과선을 새로 두지 않는다.

## 반례와 완료 게이트
- LONG/SHORT 대칭, TP/부분SL없음, 동일가격·여러단계, 100%청산, floor/최소수량/잔량,
  수수료 UNKNOWN·유효·stale, 최초진입과기존보유 분리, 입력변조/hash-binding, 원 risk 산정 불변.
- 첫TP후SL/첫부분SL후TP의 수량·손익을 독립 오라클과 대조한다. 목표합계를 확률기대값으로 만들지 않는다.
- 실제 보관 입력으로 추가 payload 크기와 DRAFT→계산→SELECT 통합 경로를 오프라인 점검한다. 100KB 상한을 늘리지 않는다.
- 관련회귀와 BTC전체오프라인테스트, 독립리뷰, CI를 거친다. 실제모델행동·운영첫실행·수익개선은 별도 상태로 보고한다.
- 검증 실패 또는 입력 여유 문제가 있으면 배포 보류하고 이유를 기록한다. 옛 A/B를 재시작하지 않는다.

## 상태
구현 및 관련 회귀 검증 완료. 전체 회귀/실제 모델 진단/CI/배포/자연관측/수익개선은 별도 게이트다.

## v2 사전 검증 계약: 손실은 짧게, 수익은 길게

2026-10-22 사용자 승인으로 보완한다. v1 실제 SELECT 한 번은 계산 경로의 명시적
비교가 관측되지 않아 `NOT_OBSERVED`였고, 그 판정과 원본은 그대로 보존한다.
이번 버전은 모델 내부 사고를 증명하는 장치가 아니라 응답에서 비교 내용을 확인하는 개선이다.

- 좁은 고정 SL·부분손절 의무·빠른 익절을 북극성의 대체물로 쓰지 않는다. 진입 가정이
  유지되는 정상 흔들림과 구조적 약화를 구분하고, 확정 실패는 기존 전량 EXIT로 처리한다.
- 후보를 만들 때 앞단 TP 소진과 이후 확장에 참여할 물량을 함께 검토한다. 강한 추세의
  구조적 목표 또는 SL로 보호되는 무고정 TP를 허용하되 고정 잔여 비율·먼 목표를 강제하지 않는다.
  수량 내림으로 생긴 자투리는 의도한 러너라고 부르지 않는다.
- SELECT의 기존 `selection_token`과 `rationale` 두 필드 계약을 유지한다. 자유서술 안의
  짧은 `계획/경로/연장` 항목으로 후보, 경로 비교, 앞단 소진·연장 근거를 관측한다.
  숫자는 호스트 계산을 그대로 참조하며 경로 확률·기대순익을 새로 계산하지 않는다.
- 네 경로의 마지막 hard SL은 스트레스 가정이지 정상 진행의 최종 목표·예측이 아니다.
  부분SL 후 반등의 이익 참여 감소와 TP 후 반전 손실을 모두 비교한다. 부분SL이 없거나
  전량TP가 적절한 후보도 허용하며, 이유만으로 새로운 강제 WAIT 관문을 만들지 않는다.
- 평가 메타데이터·파서·추가 필수 출력 필드를 거래 실행이나 exact replay 경계에 넣지 않는다.
  비교 항목 누락은 별도 검증에서 미관측이며 EXIT나 보호의 실패 조건이 아니다.

검증 순서와 판정은 수정 전에 고정한다.
1. LONG/SHORT, 전량TP, 부분SL 없음, TP 없음, 내림잔량, 위험 credit 불가,
   holding/FAILED 기존 동작과 출력 계약 불변을 오프라인 회귀로 확인한다.
2. 보관 입력 크기를 배포 기준 `b4603d753832cd755ed9d2d19915255e767f9603` 및 v1과 대조한다.
   입력 상한을 늘리지 않으며 새 크기 실패는 배포 보류 사유다.
3. 부모 작업에서 고정할 보관 사례 두 건을 운영 기준과 후보 버전으로 짝지어 진단한다.
   DRAFT→SELECT 최대 두 호출씩, 전체 HTTP 호출은 최대8회다. 주문·재시도·통과 추격은 없다.
   사례와 해시·역할별 판정은 호출 전에 별도 등록하며 같은 결과를 보고 기준을 바꾸지 않는다.
4. 모델이 경로의 기회비용과 앞단 소진/확장 근거를 응답에 명시했는지 독립 검토한다.
   표제나 경로 ID 나열만으로 의미 비교 통과라 하지 않는다. WAIT도 같은 기준으로 평가하며
   해당 후보/SELECT가 생성되지 않으면 미관측이다. 모델 내부 활용·수익 개선은 주장하지 않는다.
5. 관련/전체 오프라인 검사, 독립 리뷰, 정확한 head의 전체 CI 통과 후 데모 배포한다.
   첫 자연 판단과 실제 익절·손절 체결, 승률·평균 이익·평균 손실·손익비 개선은 별도 상태다.

### 입력 크기 검증
- 과거 eligible flat OPEN SELECT45건의 기존 projection 수치는 불변이며 최종 추가 후 최대99,112바이트였다.
- 보관 입력에 부분SL2개와후보1/2개를 붙인94개오프라인통합검사에서 기존46개입력초과·2개잘못된TP차단과
  동일한 실패 분류를 확인했다. 새 초과1건은 경로의 중복 leg표시를 제거한 뒤 해소했으며 성공 입력 최대99,904바이트였다.
- 기존2후보 입력 여유 문제는 해결됐다고 주장하지 않는다. 한도100KB·후보수상한·시장근거·위험검사는 불변이다.
- 경로는 version1의 `[순서이름목록,최종SL직전잔량,전체총손익,수수료추정배열또는null]`로 표현한다.
  원래 targets와고정경로순서에서 최초수량·잔량cap·minimum규칙으로 leg를 재현할 수 있다.
  압축은 중복 표시만 줄이며 모델 설명은 공통 SELECT 지침에 명시한다.

## v3 사전 검증 계약: 실제 적용된 경로 이름

v2 실제 진단은6회 HTTP 호출에서 LONG의 부분SL 없는 계획에도 `SL1_TP`가 표시되어
모델이 존재하지 않는 부분손절을 설명한 반례를 확인했다. SHORT는 후보가 없어 미관측이다.
v2 결과는 실패/미관측으로 보존하며 재호출로 덮어쓰지 않는다. 수치 계산은 맞았지만
없는 다리를 생략한 뒤에도 원래 경로 이름을 남긴 것이 원인이므로 이름을 교정한다.

수정 전 기준: wire version2에서는 수량 cap·최소수량 적용 후 실제로 적용된 TP/부분SL만
이름에 반영한다. 부분SL이 없으면 `TP_STOP/TP1_STOP/STOP`, TP가 없으면
`SL_STOP/SL1_STOP/STOP`, 둘 다 없으면 `STOP`만 가능하다. 뒤 다리가 잔량 소진이나
최소수량으로 생략된 경우도 같다. 혼합 이름 `TP1_SL/SL1_TP`는 두 종류가 실제 적용될
때만 남긴다. 원래 수량·가격·수수료·위험·중복 경로 합치기·receipt binding은 보존한다.
SELECT는 표시된 경로만 비교하고 없는 축소/익절 단계를 상상하지 않도록 명시한다.

LONG/SHORT 대칭으로 부분SL 없음, TP 없음, 둘 다 없음, 전량TP/전량부분SL 뒤 cap,
최소수량 미달로 다음 다리 생략을 먼저 실패 회귀로 고정한다. 기존 수치 오라클도 유지한다.
v2의 수익 참여 및 축소 기회비용 비교 기준을 완화하지 않는다. 추가 wire 필드·실행 관문은 없다.
v3 수정·오프라인 검사·CI가 통과해도 v2 SHORT의 실제 후보 생성부터 선택까지 미관측을
대체하지 못한다. 현재 전체 PR은 **HOLD / 미배포**다. 통과를 얻으려는 추가 모델 호출은
하지 않으며, 단독 SELECT 두 번으로 종단간 검증이 충족됐다고 판정하지 않는다.
