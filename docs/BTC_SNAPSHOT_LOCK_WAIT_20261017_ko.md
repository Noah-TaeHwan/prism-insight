# BTC 시세 입력 저장의 제한된 잠금 대기 (M0/M3)

## 확인한 장애
2026-10-17 14:15~14:55 KST의 9개 판단과 15:05 판단은 슬롯 확보 후
시세 입력을 저장하기 전에 잠금 충돌로 종료됐다. 실패 시각은 각 슬롯의 약18초로,
매분15초에 시작하는 보호 점검과 겹친다. 보호 프로세스의 장기 고착이나 죽은 lease가
확인된 것은 아니다. 회복 정책 PR #1029 배포 전부터 존재했다.

## 제한된 수리 범위
- 시세 수집 후 `snapshot_persist`의 잠금 획득만 최대20초 기다린다.
- 기다리는 동안 DB 거래나 실행 잠금을 소유하지 않고, 보호 작업과 기존 잠금은 유지한다.
- 잠금 내부 작업·주문·모델 호출은 재시도하지 않는다. 다른 단계의 비차단 잠금도 유지한다.
- 획득 후 슬롯·입력 신선도·상태 변경을 재확인한다. 조건이 달라졌으면 모델 호출 없이 중단한다.
- 추가 계좌 시각 검사는 실제 경합이 발생한 경우에만 적용한다. 비경합의 기존 계약과
  calculated review 및 최종 실행 전 계좌 검증은 그대로 유지한다.
- 대기 만료는 해당 슬롯의 중단으로 기록하고, 실패 단계·대기 시간을 안전한 진단값으로 남긴다.
- 전략·회복 규칙·배율·한도·보호 주기·계좌·모델은 변경하지 않는다.

## 검증과 한계
짧은 경합 후 단일 판단, 지속 경합의 제한 종료, 작업 내부 예외의 무재시도,
대기 중 상태·슬롯·입력 신선도 변경, 별도 프로세스 잠금, 재생 일치를 검증한다.
전체 오프라인·동일 HEAD CI·서버 격리 스모크·첫 자연 판단은 각각 확인한다.
이번 변경은 수익성 개선 입증이나 모든 종류의 잠금 충돌 해결을 주장하지 않는다.
