# 수렴 구간 신규 진입 제한 — 적용 기준 확인 중

## 1. 변경 유형과 기준선

사용자는2026-10-27 '수렴구간에서 진입하는 경향은 반드시 고쳐'라고 지시했다. 이는 오류 수리와 다른 경제적 의사결정 변경이다. 기준 소스69a53b7e의 위험 한도·레버리지·보유 포지션 보호는 유지한다. 최근 손실2건의 통계적 우월성을 근거로 하는 것이 아니라 사용자의 거래 범위 제한을 구현한다. 수익 개선 입증은 별도다.

## 2. 가설과 판정 정의

이평선 수렴·혼재 중 순간 가격 이탈/회복과 작은 위험 배분을 근거로 잦은 진입을 허용하는 경로를 제한한다. 기존 snapshot.ma_path.confirmed_gap의 실제 절대 MA10/35 간격 변화(change_price)를 사용한다. NARROWING은직전 대비절대간격축소이며,폭이좁다는사실이나MA순서전환과같지않다. 진행봉만으로제한이반복해서풀리지않도록확정봉기준을제안했다.

필수선택이남아있다: (A)1h확정수렴이면제한, (B)1h와30m확정이모두수렴일때제한. 사용자에게두선택을제시했고아직어느것도승인됐다고가정하지않는다. 기간·조건·해제방식을몰래추가하지않는다.

## 3. 적용 경로와 보존할 기능

기존시장자료(engine/scenario_snapshot.py) → 판단입력/검산(live/scenario_runtime.py, scenario_calculated_review.py) → 호스트승인(core/llm_scenario.py) → 주문직전확인(live/scenario_execution.py)을대조했다. 현재new_risk_blocked는계좌·복구권한과연결되므로이를시장수렴의오류상태로단순재사용하지않는다.

같은전략제한이신규OPEN,ADJUST의신규entries,미체결예약갱신에서우회되지않아야한다. 예약이수렴전부터있었다면실제진입가능성이남으므로취소/재승인경로도검토한다. 취소접수는취소완료가아니고,취소중체결과부분체결은실제증거대로보호한다. 기존포지션을수렴만으로강제청산하거나보호를해제하지않는다. EXIT/REDUCE·보호강화·취소는계속가능해야한다.

수렴관망은전략상대기이지LLM장애·주문미확정이아니다. 사용자메시지와health사유를구분한다. 모델설명만수정해주문경로를열어놓거나여러층에별도상충규칙을중복추가하지않는다.

## 4. 검증

LONG/SHORT,수렴/확대/동일간격,확정/형성충돌,누락·오래된입력,시간봉경계통과,새진입/추가/예약갱신,취소접수/실제취소/취소중체결,기존보유관리반례를검사한다. 입력근거는당시원본이며사후시세로대체하지않는다. 최종적용범위가정해지면프롬프트와실제호스트/주문권한의모순도검사한다.

최근22거래의정책버전이7개로섞여있으므로차단대상을세는것은범위점검일뿐순수익개선의인과검증이아니다. 기존연속2시간실험은수렴제한미적용기준선이며그결과를후보의성과로바꾸지않는다. 유료비교한도는별도등록하고기존봉인장부를재개하지않는다.

## 5. 관측·중단·복귀

신규위험억제여부,예약우회,기존보호/청산지속을먼저입증한다. 수렴해제이후근거있는진입재개와누락기회·완료거래·비용·낙폭은따로관측한다. 기준을결과에맞춰완화하지않으며관련회귀가실패하면배포하지않는다. 위험예산확대·실자금·추가상주배치는범위밖이다.

## 6. 현재 상태

호출경로검토와적용범위초안만완료했다. 시간축선택답변대기이며정책코드·운영설정·프롬프트를바꾸지않았다. 세부구현과테스트·CI·배포·자연실행·수익성은모두미완료다.


### 선택 범위의 사전 점검

저장된 최근22거래에서 A(1h확정수렴)의 대상은11건, B(1h·30m확정동시수렴)의 대상은7건이다. 두기준모두오늘09:11 LONG을대상으로하지만08:06 SHORT는1h확정간격이확대중이어서대상이아니다. 이건차단대상범위만센것이며다른진입/후속판단이달라지는정책전체의가상손익이아니다. 따라서기준선택없이'오늘손실둘다방지된다'고주장하지않는다.
