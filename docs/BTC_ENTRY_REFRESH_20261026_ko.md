## 수정 범위와 불변 조건

새 entry child마다 기존 `monitor(refresh=True)`로 근거를 실제 재조회한 후 계좌를 캡처하고 preflight를 적용한다. 추가 조회 중 행동 자체가 만료되는 경우도 전송 전에 차단한다. 기존 child는 정확한 주문 조회만 수행하며 재전송하지 않는다. 보호·청산 처리 순서는 유지한다.

10초 유효기간, 위험 한도, 최종 전송 guard, 과거 미확정 2건의 보존·통계 제외 기준은 바꾸지 않는다. 갱신 실패, 과거 사건의 새 체결, HALT, 갱신 후 재만료는 계속 신규 주문을 막는다. 새 의존성이나 설정은 추가하지 않는다. 이 변경은 M0 실행 수리이며 수익성 개선의 증거가 아니다.
