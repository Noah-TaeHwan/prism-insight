# BTC 입력 크기 장애 수정

## 수정 전 계획

M0 입력 준비 장애 수정이다. 전략 후보 V2와 분리하며 서버 기준 bb4d3d의 판단 정책·위험·회복·출력 계약·100,000바이트 제한을 그대로 둔다. 기존 입력 테스트 12개를 수정 전 통과했다.

47개 보존 입력 중 기존 투영 후 32개가 제한을 초과했다. 같은 열 이름을 반복하는 허용된 시장 관측 목록만 열 이름과 행 배열로 무손실 표현한다. 빈 목록·서로 다른 키 순서·비균일 행은 유지하고, 숫자 타입·정밀도·문자열·모든 값을 보존한다. 작은 입력은 메타데이터를 포함해 증가하면 원래 형태로 되돌린다. 포지션·위험·회복·출력 계약의 행 구조는 바꾸지 않는다.

기존 v1 복원을 유지한다. 새 행 표현이 실제 적용된 경우에만 v2를 표기하고, 행 복원 후 기존 정의 참조와 numeric_market을 복원한다. 예약 마커, 잘못된 열과 행 길이, 미등록 경로는 거절한다. 실제 47개 입력의 타입 보존 정렬 JSON 해시와 100KB 미만을 확인하며 실모델 호출은 하지 않는다.

## 검증 결과

- 로컬 전체 회귀: **3,372 통과·12 skip**, 193.88초. 집중176개와 독립125개 검증은 중복되는 범위이므로 합산하지 않는다. Ruff F/E9·컴파일·diff-check 통과.

- 실제 보존 입력 47개: 기존 투영 97,208~100,686바이트, 32개 초과 → 새 투영 88,039~91,517바이트, 초과 0개. 최소 여유 8,483바이트다. 최신 입력은 100,454 → 91,285바이트다.
- 47개 모두 복원 후 타입 보존 정렬 JSON SHA256이 원본과 정확히 일치했다. 원본, 포지션·위험·회복 근거·응답 계약을 잘라내거나 반올림하지 않았다.
- 긴 고유 입력의 실제 propose 경로는 여전히 input_size로 모델 호출 전 차단된다. 정확히 100,000바이트는 통과하고 100,001은 차단하는 기존 회귀를 유지한다.
- 기존 prompt integration의 관측 목록 길이 확인은 raw table 검증 후 복원된 네 관측값 확인으로 바꿨다. 프롬프트 문자열·해시·전략·모델·실행 함수는 변경하지 않았다.
- 잔여 위험: 현재 47개에 대한 용량 여유이며, 무한한 입력 크기를 보장하지 않는다. 누적 seen_action_ids 등의 장기 증가가 다시 제한에 도달할 수 있다. 이 수정은 과거 위험/재생 식별자를 임의로 잘라내지 않는다.
- 배포·실제 정규 실행 확인은 별도다. 연구 후보 V2 또는 수익성 개선과 혼동하지 않는다.
