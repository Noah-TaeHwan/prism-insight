# BTC 진입·보유 청산경로 비교 보완

## 승인·범위

2026-10-23 사용자 승인: 진입 품질, 부분익절 후 손익 구조, 행동·설명 일치, 부분손절 강화. M0/M3 행동 설명 경계 수리는 `BTC_ACTION_RATIONALE_BOUNDARY_20261023_ko.md`에서 따로 추적한다. 본 문서는 M3/M4 판단 자료·프레이밍 보완이며 M5 수익성 증명이 아니다. 기준선은 Sol low 배포 `4d1c7f72`다.

## 가설과 기존 전략 적합성

- 방향이 맞더라도 실제 진입 위치와 이미 진행된 가격 변화가 불리할 수 있다. 기존 진입 지침에서 확정 종가열과 형성 중 움직임을 별도로 비교한다. MA 위·아래라는 위치를 확정봉 상승·하락으로 해석하지 않는다. 반대 종가열 자체를 진입 금지로 만들지 않으며 강한 즉시 돌파·합리적 조건부 교차는 유지한다.
- 기존에도 보유 중 Mark/전량SL의 비용 반영 전체 손익은 runner_economics로 제공했다. 수수료가 전혀 없던 것이 아니다. 빈틈은 새 ADJUST의 여러 TP·부분SL 경로를 전체거래 기준으로 비교하는 자료가 없었다는 점이다.
- 새 ADJUST에서는 구조적 부분감축·현재 보호 유지·전량 종료를 비교한다. TP만 당기고 잔량 위험을 그대로 두는 선택의 비용도 판단한다. 부분SL 의무화, 고정 RR·비율·거리·본전SL, 즉시 부분시장가 실행은 추가하지 않는다. FAILED 전량 EXIT와 기존 위험 예산은 유지한다.

## 계산 및 입력 경계

기존 flat joint_exit_paths version2와 hash-bound 후보 receipt는 변경하지 않는다. 계산은 기존 `_gross_projection`·`_joint_exit_paths`를 재사용하되, **확정 잔량을 대상으로 하는 새 ADJUST**에만 version3 표시를 별도 생성한다.

`contract_context.holding_exit_paths`의 각 행은 `[candidate_id, receipt_sha256, version3_paths]`다. 후보 본문 hash·검산 당시 context hash를 확인하고, `pricing_basis.validation_now`로 결박된 당시 비용 유효성을 사용한다. view는 후보 선택·실행 권한이 아니다.

- 경로 gross는 현재 잔량의 가격 손익뿐이다.
- fee_only의 entry fee는0이며, net은 **기록된 전체거래 net + 잔량 경로 gross − 가정한 향후 청산 수수료**다. 기록 net은 경로당1회만 반영한다. 과거 진입/익절 수수료·펀딩을 다시 차감하지 않는다.
- 기록 net이나 관측 요율이 결측·비정상이면 해당 비용 추정은UNKNOWN이다. 실제 미래 수수료·펀딩·슬리피지·체결 여부는 계속 미확정이다.
- 새 revision의 목표 quota와 최소수량·내림·잔량 cap을 재사용한다. 이미 익절한 수량을 복원하지 않는다. 미체결/신규 진입 가정에는 경로를 붙이지 않는다.
- WAIT는 기존 runner_economics의 Mark/SL 진단을 쓴다. 기존 current_plan 비율을 현재 잔량에 다시 곱하면 과거 체결한 TP를 재생성하므로 그렇게 하지 않는다.
- 각 경로의 남은 수량을 전량SL에 종결시키는 것은 스트레스 가정이지 추세 지속의 기대값이 아니다. 이 계산만으로 러너를 없애지 않는다.

입력은 먼저 기존 position_flow 예산 투영을 완료한다. 그 결과를 복원한 뒤 optional view를 추가하고 손실 없는 입력 압축만 시도한다. 100KB를 넘으면 기존 baseline을 그대로 사용한다. 시장·회계·후보·이력·원문을 더 삭제하지 않는다. view 부재는 미확인이며 WAIT·보호·EXIT의 새 차단 사유가 아니다.

## 사전 검증과 반증

원래 active 경로 부재를10개 회귀 실패로 확인한 뒤 구현한다. 양방향·기록 net 양수/음수/0/결측·요율만료·context/receipt 변조·과거 부분체결·미체결 혼합·최소수량·부분SL 후 회복·TP후잔량SL을 검증한다. flat v2, 후보 가격·수량·위험·선택자격은 보존해야 한다. 두 후보·많은 목표·기존99KB대 입력에서 신규 차단이나 추가 이력 손실은 허용하지 않는다.

실제 모델 검증 전 고정 원자료·버전·호출 상한·판정 기준을 별도 등록한다. 최신 손실과 과거 수익 사례는 개발 표본이지 holdout이 아니다. 모델이 반드시 진입하거나 부분SL을 선택하도록 요구하지 않는다. 추가 계산을 잘못 더하거나 설명의 행동 귀속이 틀리면 실패다. 필요한 비교가 나타나지 않으면 미관측이지 통과가 아니다.

## 현재 상태와 종료 조건

구현·오프라인 검증 중이다. 실제 모델 검증·CI·데모 배포·첫 자연 관측·수익 개선은 각각 별도 증거로 갱신한다. 가격 인용/행동 귀속/회계/시간 상한의 오류가 남으면 해당 범위는 배포하지 않는다. 기존 종료 연구를 재실행하지 않으며 실패 기준을 낮추지 않는다.

배포 뒤 안전 결함이 나타나면 활성 계약·잔량 보호를 우선 확인하고 호환되는 좁은 수정/복귀를 한다. 최근 손익만 보고 자동으로 규칙을 왕복하지 않는다. 본 작업의 종료점은 구현·검증·배포·첫 자연 판단 확인이며, 승률/수익 개선은 별도 전진 관측이 필요하다.
