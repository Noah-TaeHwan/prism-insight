# 추세 기본·제한 구간 후보 정책: 검증 전

## 사용자 승인과 범위

2026-10-25 사용자는 추세추종 기본, 제한구간 고승률·비용후 기대값 중심의 전략을 검증하고 확정한 뒤 수정·데모 배포하도록 승인했다. 향후 제한구간20배 검토 의향은 현재 레버리지 변경 허가가 아니다. 실자금·위험한도·보호주기 변경은 없다.

대상 M3/M4 판단층과 계산 근거다. M5 수익성입증과 기능 검증은 별개로 기록한다. 새로운 유형라벨을 원계약에 소급 주입하거나 기존regime/MA목표경계만으로 매매목적을 단정하지 않는다.

## 수정 전에 고정한 계획

1. 기존 원진입23건의 원계약·원시세를 읽기전용으로 보완하고 손익 결과가 없는 입력으로 목적을 독립 분류한다. 이는 이미 검토한 개발기간이며 holdout은 아니다.
2. 제품 후보는 기존 calculated DRAFT/SELECT 판단층에 한정한다. 추세의미있는잔량과 제한구간회수를 구별하고 수수료최소화가 아닌 순기대값을 비교한다. 고정익절비중·고승률숫자·일괄2:1진입차단·즉시20배는 넣지 않는다.
3. 기존 flat OPEN 경로 계산을 재사용해 전체목표 경로의 수수료가정 순이익/부분손절미체결 전량SL 순손실을 호스트가 표시한다. 새 계산기로 수량·주문을 바꾸지 않는다. 비용缺·손실분모비양수는UNKNOWN이다. 미래펀딩·슬리피지제외,도달확률미포함임을명시한다.
4. 테스트를 먼저 추가하고 기존단위/연결/입력크기/원문해시·변조반례를 보존한다. 롱숏대칭·0/최소수량·부분SL·비용缺·holding/legacy 경계를 확인한다.
5. 독립검토→정확head오프라인검증→사전고정한주문없는실모델비교를 거친다. 기존실패실험을초기화/재호출하지않으며 새시험의입력/예산/판정/미충족을보존한다.

## 통합 검증에서 확인한 선행 누락과 보완 범위

실제 원래 flat 입력4건의 DRAFT→SELECT 재생에서 수수료가모두UNKNOWN임을확인했다. broker.context는무포지션일때빈accounting을사용하고검증수수료는보유회계에서만생성되어,표시산식만추가해도정상flat에서값이없다.

이를고치기위해기존broker_evidence의전용단일cache종류에**앞으로실제확정회계에서얻은TAKER근거만**보관한다. expectedUID·demoendpoint·BTCUSDT·원수집시각·원execution시각/sourceSHA에결박한다.같은근거재조회로유효기간을갱신하지않는다.과거이력보충/임의요율/새API호출없음.
flat읽기는현재신원확인·control.main_uid일치·무보유·단일정상레코드·원TAKER24시간유효성을전부요구한다.없거나오래되거나틀리면UNKNOWN.캐시실패가회계·위험·보호·EXIT를차단하지않도록격리한다.첫배포때과거cache가없으면새검증보유회계가생길때까지UNKNOWN이정상이다.
실제계좌별현재요율이아닌**동일계좌의검증된과거요율가정**임을유지한다.이선행기능도별도회귀·프로비넌스연결·전체검증을받으며,전략수익개선의증거로바꾸지않는다.
