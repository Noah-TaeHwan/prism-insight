# M2/M4 목표 계약을 포함한 장기 재생 설정

## 문제와 범위

현재 운영 runner는 entry-contract와 calculated-review가 켜지면 `entry_contract_enabled`, `entry_goal_enabled`, `pending_renewal_enabled`를 함께 사용한다. 기존 `analysis/scenario_replay.py`의 경제성 프로필은 복구/정상화만 켰다. 따라서 기존 장기 재생을 현재 목표 계약을 포함한 전체 보유 정책의 검증으로 부르면 틀리다. 별도로 런타임 플래그를 켠 최근12쌍 초기계획 실험의 입력과는 다른 경로다.

`economic-reject-goal-v2`를 명시적으로 선택할 때만 세 기능을 켠다. 경제성 후보/선택 모드는 기존 `economic-reject-calculated-v1`을 재사용한다. 프로필을 새로 만든 이유는 과거 기록의 의미를 바꾸지 않기 위해서다. 기존 프로필·기본값·위험 한도·프롬프트·실제 주문 로직은 유지한다.

재생 계약에는 켜진 runtime_flags와 entry_contract_version2/pending_renewal_version1을 기록한다. 비교 도구의 프로필 허용 목록 및 경제성 거절 재집계에도 같은 프로필을 연결한다. 선택하지 않은 기존 경제성 연구 coordinator의 고정 비교 프로토콜을 자동으로 새 정책으로 바꾸지는 않는다.

## 검증

신규 경로 등록 전 테스트3개가 명시 프로필 미등록으로 실패하는 것을 확인했다. 이후 다음 실제 런타임→격리 거래소→저장→정확 재생 검사를 수행한다.

- 원래 프로필 플래그 불변과 새 계약 메타데이터 확인.
- 제한 없는 목표와 유효한 MA 상한 목표의 진입·체결·보유 판단에서 v2 계약 유지.
- MA 상한을 넘는 후보는 `entry_goal_bound_exceeded`로 제외되고 WAIT로 종료하며 계약/진입을 만들지 않음.
- 기록/재생 결과 해시 일치, 재생 모델 호출0 및 네트워크 시도0.
- 새 프로필 기록을 옛 프로필로 재생하면 계약 불일치로 거절.
- 기존 경제성 거절 집계·비교 계약·경제 시계 회귀 검사.

합성 fixture 검증은 모델의 전략 판단이나 수익성 입증이 아니다. 실제 관측 입력을 쓸 연구에서는 입력 시각과 원본 해시를 고정하고, 전체 보유 중 모델 호출을 최대48회 안에 사전 배분한다. 현재 운영의 과거 격리 사건/실계좌 상태를 새 합성 DB에 복제했다고 주장하지 않는다. 현재 활성 세 기능을 포함한 재생 경로이며 전체 운영 환경과 동일하다는 뜻이 아니다.

## 사용

기존 `analysis/scenario_replay.py` 명령의 `--policy-profile economic-reject-goal-v2`로 선택한다. 기본 프로필은 바꾸지 않는다. 유료 모델 실행은 별도 사전등록·CallGuard·원 입력/가격 검증을 통과한 연구에서만 수행한다. 이 변경으로 상주 배치·실자금·새 운영 주문은 추가되지 않는다.
