# BTC 설명 감사의 좁은 검출 범위 확장

M3 관측 전용 수리다. 매매 프롬프트·판단·주문·보호·원문·재생 봉투는 변경하지 않는다.
도우미는 독립 CLI에서만 사용한다. 검사 실패는 보고서의 UNVERIFIED이며 EXIT 차단 근거가 아니다.

## 원인과 변경

기존 검사는 TF 토큰 자체와 `frame phase field value` 형식만 좁게 대조했다.
따라서 토큰 앞의 잘못된 라벨, `frame field phase(value)` 형식, 두 확정 종가의
변화 인용, MA와 현재 Mark의 위치 설명은 검출 범위 밖이었다.

- 명시한 단일 시간봉·필드·확정/형성 라벨 바로 뒤의 수치 또는 TF 토큰을 대조한다.
- `확정 30m 종가는 A에서 B로 내려가…`처럼 좁은 두 종가 인용에는 최신 연속 확정봉
  두 개를 참고 사실로 붙인다. **최근 두 봉이라고 명시한 경우에만** 기계적 MATCH/MISMATCH를
  판정하고, 시점이 불명확하면 UNASSESSED와 수동 대조 안내를 출력한다.
  과거·기준선·조건부 인용과 복수 시간봉 등 모호한 문장은 평가하지 않는다.
  두 원본 봉이 연속·고유·확정인지 확인할 수 없으면 UNVERIFIED다.
- 같은 라벨과 TF 토큰 직후에 현재가·현 가격·Mark 위/아래라고 명시한 짧은 절만
  참고 `context.mark_price`와 함께 표시한다. **MarkPrice/MARK_PRICE라고 명시해야**
  기계적 위치 판정을 하며, 일반적인 현재가가 Mark인지 Last인지 불분명하면 UNASSESSED다.
  진입가 등 다른 기준·조건문·별도 문장에는 적용하지 않는다.
- CLI는 수치 오류, 라벨 오류, 위치 오류를 구분해 실제 대조 근거를 표시한다.

## 확인한 사례

- 13:15의 `12h MA10 confirmed(82228.57…)`: 원본은 **82328.57**이다.
- 13:50의 `12h MA10 confirmed [[TF:1h:confirmed:close]]`: 라벨과 토큰이 다르다.
  토큰 자체의 유효성과 주변 설명의 정확성은 별개다.
- 15:15의 30분 종가 `82782.3→82751.7`: 최근 두 확정 종가는 `82915.9→82782.3`이다.
- 16:50의 4시간 형성 MA35는 약 `82197.9171`로 Mark `82200.23`보다 아래다.

17시 감사의 보존된 63개 응답에서 첫 두 건은 자동 MISMATCH로 대조했다. 나머지 두 건은
비교 시점·가격 기준이 생략돼 UNASSESSED와 참고 사실을 표시하며, 원감사의 수동 판정과
구분한다. 자동으로 네 건 모두를 확정했다고 주장하지 않는다. 전체 자유 서술이 정확하거나
향후 모델의 오류 생성이 방지됐다는 뜻은 아니다. 보고서가 원본 값을 다시 옮겨 쓸 때 발생한
`83328.57` 오기도 모델 원문의 오류와 구분해야 한다.

## 범위 밖

일반 자연어 해석기나 모델 출력 수정 기능이 아니다. 임의의 복수 MA 비교, 상대적인
과거 시점, 조건부·미래 문장, 생략된 시간봉/단계는 여전히 미평가다. 일부 검사 MATCH 또는
MISMATCH 0건을 전체 설명의 정상 판정으로 쓰지 않는다. 운영 수리·배포·첫 자연 관측은
이 문서의 구현 및 오프라인 검사와 별도로 확인한다.
