# BTC 다단계 판단 기록과 별도 서버 보관 (M3)

## 승인 범위
사용자는 다단계 판단 기록의 ClickStack 연결과 원본 장기 보존 보완을 승인했다.
매매 전략·프롬프트·모델·위험 한도·주문 경로는 변경하지 않는다. 전략 일반화 검토는 별도 읽기 전용 보고다.

## 기록 경로
- 기존 4개 스트림은 유지하고 `llm_scenario_review_events`와 `llm_scenario_review_tapes`를 추가한다.
- 새 두 스트림만 보존된 처음 행부터 제한적으로 채운다. 최초 관측 상한을 기록하고 커서와 대조해 진행·완료를 확인한다.
- 슬롯·순번·후보/선택 단계·모델 설정·요청/응답/검산/테이프 해시와 허용된 수치만 내보낸다.
- 프롬프트·원응답·자유문장·계정 식별자·자격증명은 중앙 로그로 복사하지 않는다.
- 원본 코드 근거는 정확한 슬롯의 decision_input manifest만 연결한다. 현재 exporter 버전을 과거 버전으로 대체하지 않는다.
- 판단 이벤트는 audit보다 먼저 저장될 수 있다. 당시 UNKNOWN은 그대로 보존하고, 뒤따른 audit와
  source identity·정확한 슬롯·입력 ID 해시로 연결한다. 모든 행에 직접 코드가 붙었다고 주장하지 않는다.
- 실제 사건 시각이 없으면 source_event_time은 null이다. 전송 관측 시각은 별도로 보존한다.
- 읽기 전용 snapshot 안에서 슬롯별 manifest 조회를 재사용하며 다음 snapshot으로 캐시를 넘기지 않는다.
- 기존 행·4MiB 원본 처리·outbox 한도, fsync·동일 ID 재시도, 불량 행의 커서 보존을 유지한다.

## 원본·Git 분리 보관
기존 일일 백업은 SQLite online snapshot·압축·복원 해시 검증을 수행한다. 그 다음 단계에
기존 SSH 경로를 사용한 별도 서버 비공개 보관을 추가한다. 새 cron·daemon·외부 서비스는 없다.
전송 대상은 검증 DB 압축본, manifest, Git bundle, 명시적인 archive metadata뿐이다.
별도 서버에서 원본 해시·크기·SQLite 검사와 Git 복원·유효 참조 commit·fsck를 확인한 뒤 게시한다.
Git에서 현재 refs로 도달하지 못하는 유효 참조 commit도 임시 mirror의 참조로 포함하고 원본 refs는 수정하지 않는다.
UNKNOWN·누락·잘못된 코드 참조는 coverage에 남긴다. 알려진 commit 누락은 성공으로 처리하지 않는다.
과거 Git 이력까지 비밀정보가 전혀 없다고 보장할 수 없으므로 아카이브는 root 전용700/600으로 격리한다.

## 보존 정책·실패 경계
- 원격 자동 삭제는 추가하지 않는다. 최근 일일2개+월별12개 정리는 별도 사용자 결정 사항이다.
- 5GiB 여유 공간과10GiB 작업/보관 상한을 적용한다. 상한에는 복원용 임시 공간도 포함된다.
- 공간·인증·해시·복원 검증 실패 시 이전 사본을 보존하고 성공 ACK를 발급하지 않는다.
- 원격 ACK가 없으면 기존 로컬7일 정리도 실행하지 않는다. 실패/비활성은 로그·비정상 종료로 드러낸다.
- 같은 서버 백업이나 ClickStack 수신만으로 재해 복구를 입증하지 않는다.

## 완료 판정과 한계
관련·전체 테스트, 동일 HEAD CI, 서버 배포, 자연 exporter 처리, 특정 원본과 ClickHouse 수신의 해시 일치,
별도 서버 복원 검증 ACK를 구분해 확인한다. 테스트 성공 자체는 운영 수신 성공이 아니다.
이 작업은 현재 보존된 원본의 지정 범위를 연결·보관하는 것이며, 기록하지 않았던 과거 시세·호가·모델 판단을
만들어내지 않는다. 모든 과거 코드의 완전한 재현이나 수익성 개선을 입증한 것은 아니다.
