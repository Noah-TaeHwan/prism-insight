# BTC 판단·계산 분리 경제 재생 검증

범위는 M3 기록 정합성과 M4 개발 실험이다. M5 수익 개선과 운영 활성화는 미입증이다.

## 비교 계약

- A `single-pass-economic-v4`, B `calculated-economic-v4`를 같은 관측 자료와 모의 계좌 조건으로 비교한다.
- 모델이 전략 가격·비중을 선택하고 코드는 비용·위험을 검산한다. 새로운 고정 TP/SL 전략은 추가하지 않는다.
- 전체 판단·기록·검산 중 실제 경과 시간을 경제 시간에 반영한다. frozen은 보존된 시간과 사건을 재생하며 모델을 호출하지 않는다.
- 최종 검산 후 실제 경제 사실이 바뀌면 적용을 거절한다. 검증된 관측 시각·보유 시간 증가만 허용하며 가격·체결·보호 변화는 숨기지 않는다. 이 보수적 거절도 결과에 남긴다.
- 실패한 기록에서 이미 저장된 효과와 저장되지 않은 효과를 구분한다. STOPPED는 끝까지 보호만 진행해도 비교 적격이 아니다.
- 기존 단일 판단 테이프와 schema는 유지한다. 새로운 다단계 테이프를 기존 결과처럼 해석하지 않는다.

## 1단계 실행

`tools/btc_calculated_economic_study.py prepare`는 원본 자료·소스·계약·독립 회계 입력을 고정한다.
`run`은 별도 명시 실행이며 첫 4슬롯, A/B와 OHLC/OLHC 네 계좌, 실제 HTTP 최대 24회다.
최초 기술 오류에 전체 신규 호출을 중단한다. 실패 자료와 가능한 실패 frozen을 보존하고 재시작하지 않는다.
실제 HTTP 직전에 최종 요청 해시를 기록하고 예약한다. dispatch와 실제 HTTP 횟수는 다르며 모르는 값을 0으로 채우지 않는다.
실행기 자체·호출 제한기·HTTP 어댑터·비교기도 소스 핀에 포함한다.

1단계는 개발 도구 검사다. WAIT만 나온 완료, 거래 없는 완료, 재생 일치는 수익 개선 증거가 아니다.
확대 실험은 별도 등록하며 독립 표본·비용 2배·낙폭·다중검정 등 기존 M5 기준을 완화하지 않는다.
펀딩 시각의 직전 확정 Mark를 쓰는 재생 가정은 실제 거래소 펀딩 Mark 원본과 구분한다.

## 구현 검증

### 별도 2단계 개발 비교

실행기는 명시적으로 등록하는 두 단계만 지원한다. 1단계 offset0/4슬롯/24HTTP는 유지하고,
2단계는 원본 관측 자료의 offset4/24슬롯/144HTTP로 고정한다. 임의 구간 선택이나 자동 확대는 없다.
2단계는 이전 registry의 외부 파일 SHA, 네 계좌의 완료·재생·테이프·원응답·호출 원장을 읽기 전용으로 검증하고
매 호출 전에 이전 자료와 현재 소스의 불변성을 검사한다. 전략·위험·프롬프트·계산 영수증은 바꾸지 않는다.
각 계좌는 동일 자본과 recovery-stage0로 새로 시작하며 이전 계좌 상태를 이어받지 않는다.
한 개발 기간이고 OOS/forward 표본은 0이다. MDE·검정력은 미산출이며 경로·호출 횟수를 독립 표본으로 세지 않는다.
무체결은 경제 기능 노출 부족이다. 실제 실행은 새 테스트·CI·사전등록 영수증 이후에만 진행한다.

### 1단계 구현 근거

후속 2단계 v1은45HTTP에서 모델의 현재 최초 관측 분류 오류로 중단됐다. 이전 실패 결과는 그대로 보존한다.
새 draft는 wait_proposal/candidates/no_candidate_reason 세 필드만 요구한다. host는 현재 최초 상태와 실제 제출 배열로
분류하고 HOST_DERIVED_FROM_STATE_AND_ARRAY로 기록한다. 비최초 빈 배열은 NO_CANDIDATES_SUPPLIED이며 시장 기회 부재의 증명이 아니다.
WAIT fallback·저장 기준선의 유래·현재 최초 여부를 설명에서 구분한다. 잘못된 자유 사유는 수정하지 않고 미검증 원문으로 보존한다.
추가 legacy 분류 필드·초과 후보·사유 누락·wire 오류는 계속 거부한다. 가격·위험·75초·최종 fresh 일치 검사는 그대로다.
관련362테스트를 통과했으며 새 전체 검증·CI·기술 v3 등록 후 확대한다. 기존8db 연구를 재시작하거나 적격으로 고치지 않는다.

확대 전에 후보 가격 계산의 시각 기준 결함을 추가로 발견했다. 동결 호가에 초안 응답 후의 현재 시각을
적용하면 optional 가격 보정을 생략하고, 최종 fresh 보정에서는 같은 시장이어도 가격이 달라져 B만 거절됐다.
preview 전용 진입점은 원래 INPUT now를 호가 나이 기준으로만 사용한다. 실제 timestamp를 고치지 않으며
모든 현재 만료·입력 나이·위험 검증과 최종 fresh 가격·위험 일치는 유지한다. live 진입점 동작은 그대로다.
수정은 RED 재현 후 관련259테스트로 검증했다. 새 전체 테스트·CI와 별도 stage1 v2 기술 등록 이후에만
확대한다. 기존 v1 연구는 보존하며 v2를 독립 수익 표본으로 세지 않는다. stage2의 source 동일성 검사를 우회하지 않는다.

- 1차 전체 격리 테스트: 3,847 통과, 12 skip, 실패 0, 네트워크 시도 0. 후속 SQL 조회 안전성 수정은 새 테스트·CI 영수증으로 확인한다.
- 실제 실행기·호출 제한기·비교기를 연결한 fake HTTP 검사와 호출 전 기록 지연으로 dispatch 1/HTTP 0이 되는 반례를 포함한다.
- Ruff(기존 E701/E702 제외), diff 검사와 독립 소스 검토를 통과했다.
- CI, 사전등록, 실제 모델 실험 결과는 각 실행 영수증으로 별도 확인한다. 이 문서는 실제 모델 비교 완료나 배포를 주장하지 않는다.
- 기본 운영 경로는 OFF이며 실제 주문·운영 스케줄·기존 실험은 변경하지 않았다.
