# BTC 판단과 계산 분리 · 구현 및 검증 계약

## 승인·목적·범위
사용자는 진입가·TP·SL·분할 비중·주문 전략은 LLM이 유연하게 결정하고, 원자료 조회 및 정해진 파생 계산과 검산은 코드가 맡도록 승인했다. 이번 작업은 M3 입력/증거 정합성과 M4 판단 경계 개선이다. 수익 개선이나 M5 완료를 전제하지 않는다.

기존 main 4825b861에서 시작한다. 가격 흐름 프레이밍 v1/v2 및 비용 설명 v3는 미배포 연구이며 자동으로 합치지 않는다. 기존 위험 한도·손절/익절 전략·회복 허가·모델·OAuth 인증 방식은 유지한다.

## 구현 순서
1. 기존 MA·거래량·가격 위치·계좌 입력을 재사용한다. 이미 계산된 수치를 LLM이 재계산하게 하지 않는다. 없는 자료는 unknown/unavailable이다.
2. 먼저 무포지션·미체결 없음 문맥의 주문 없는 연구 진입점을 만든다. LLM이 WAIT안과 최대2개의 자유로운 가격·수량 후보를 제시한다. 구조 근거가 부족하면 후보를 만들도록 강제하지 않는다. 경제성 때문에 거절할 때는 비교 가능한 후보를 제시해야 검산할 수 있다.
3. 원래 wire·위험·가격 보정 검증 함수를 재사용한다. 원본 가격과 기존 정책상 보정된 유효 가격, 정확한 위험, 전량 체결 가정의 부분 TP 손익을 구분해 계산한다. 계산 결과가 진입 신호나 실행 허가가 되는 것은 아니다.
4. LLM은 검산 결과를 읽고 불변 후보 ID 또는 WAIT를 최종 선택한다. 두 번째 답변에서 가격·수량·만료를 바꾸지 못한다. 수정이 필요하면 이번 선택을 포기하고 새 후보가 다시 검산되도록 해야 하며 무한 재호출하지 않는다.
5. 연구 결과는 명시적으로 executable=false이다. 운영 실행과 회복 허가, 경제 재생에 연결하기 전 각 경계의 적합성을 별도로 증명한다.

## 처음부터 제한하는 이유
보유 중 TP 수량은 체결·기존 목표 소진량·추가 체결을 반영한다. 현재 재생 기록은 단일 호출 요청/응답을 가정하며, 실행 직전 시세에 따라 기존 가격 보정 결과도 달라질 수 있다. 따라서 연구 경로를 곧바로 운영 propose로 대체하지 않는다. 무포지션 연구에서 계산 전달·변조 방지·지연을 확인한 뒤 보유/부분체결·단계별 재생·실행 직전 동일 가격 확인을 연결한다. 이 미연결 범위를 구현 완료나 배포 완료로 보고하지 않는다.

## 안전 계약
- 한 판단의 공통75초 한도에 첫 호출·계산·최종 호출을 모두 포함한다. 각 단계마다75초를 새로 주지 않는다.
- 원래 입력 유효시간120초, 계좌 관측 시각, 원래 주문 만료와 회복 허가를 유지한다. 응답 지연·부족한 근거·오류는 새로운 주문으로 바뀌지 않는다.
- 단계별 실제 요청·응답·해시·소요 시간을 기록한다. 첫 단계 응답만으로 최종 판단 성공을 표시하지 않는다.
- 실제 비용률 미확인을0으로 채우지 않는다. estimated_cost_rate는 합산 위험 준비금이며 편도 실수수료가 아니다. 손절 슬리피지는 별도다. TP 가격 차익은 비용 전/전량 체결 가정이며 실제 순익 보장이 아니다.
- 코드가 더 좋은 가격·수량·TP를 선택하거나 위험 한도를 완화하지 않는다. 기존 실행 가격 보정은 원본과 유효값을 함께 공개하며 이 연구에서 정책을 바꾸지 않는다.
- 후보/계산 영수증/시점 해시를 묶는다. 최종 응답은 없는 ID, 다른 해시, 미검산 수정안, 경제적으로 거절된 후보를 선택할 수 없다.
- 이미지·실제 주문·운영DB 변경·크론 변경·기존 연구 재시작은 없다. 새 의존성을 추가하지 않는다.

## 성공·반례 검증
- 실제 호스트 위험 공식과 롱/숏 산술 일치. 이전 오류 E83410/SL82900/rate0.002/slip20bp에서 BTC당842.62를 재현한다.
- 첫 관측 WAIT, 후보 없는 구조 근거 부족 WAIT, 검산 후 경제성 WAIT가 구분된다.
- 틱·최소 수량·위험 한도·가격 보정·잘못된 방향·결측·NaN·과대 입력·후보 수 상한을 검사한다.
- 후보 ID/해시/가격 변조, 첫 호출 성공 후 두 번째 실패, 시간 초과, 계좌/입력 시각 이상은 실패한다. 실패한 연구 결과를 거래소 상태나 기존 보호 해제로 취급하지 않는다.
- 기존 propose·runtime·broker·위험 산식의 운영 동작은 그대로이며 전체 오프라인 회귀 테스트로 확인한다.
- 실제 모델 비교는 별도 사전등록 후 원본을 보존한다. 후보 선택 증가 자체를 수익성 개선으로 판정하지 않는다.

## 최소 검토 기록
1. 가설: 자유문 산술을 신뢰하지 않고 계산 사실을 모델에 돌려주면 경제성 판단의 수치 오류를 줄일 수 있다.
2. 기존 전략 적합성: 지지·저항 해석과 가격/비중은 모델이 유지하고 실행 안전과 계산은 코드가 담당한다.
3. 모순 경계: 초기 후보는 주문이 아니다. 최종 선택은 검산된 불변안만 사용한다. 준비금과 실제 비용, 부분 TP와 전체 순익, 연구와 운영을 분리한다.
4. 검증: 위 단위·경계·전체 테스트 및 주문 없는 고정 모델 비교를 수행한다.
5. 채택 기준: 산술·해시·시각·입력·오류 경계와 단계별 증거가 모두 확인돼야 다음 통합 단계로 간다. 수익성은 별도 검증한다.
6. 롤백/미반영: 현재 단계는 기존 운영 경로를 건드리지 않는 연구 진입점이므로 운영 롤백 대상이 없다. 검증 실패 시 실패 자료를 보존하고 실행 연결을 하지 않는다.
