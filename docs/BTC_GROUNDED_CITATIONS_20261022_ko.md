# 시간봉 가격 인용의 원본 연결 수리

## 원인과 범위
M3/M4 설명 근거 수리.23:30 slot5975310은 DRAFT가올바른1h형성83897.4를인용했으나SELECT가1d83893.7로바꿨다.
00:20 slot5975320은DRAFT wait_proposal.rationale에서30m확정84549.9를15m84668.9로인용했다.
두입력원본은정상이다. 후자는no-SELECT WAIT이며최종rationale는별도의no_candidate_reason이므로잘못된문장이최종그대로저장됐다고하지않는다.
자유문에서수치를재작성하고경로·phase·값을대조하지않는설명경계가확인된구조적원인이다. 모델내부오독과실제판단영향은미확정이다.

## 안전한 수리 계약
- 원 MODEL_RAW·제안·intent·등록계약·선택토큰·위험·주문값은보존한다. 과거숫자를조용히고쳐모델이정확했던것처럼만들지않는다.
- 설명전용 비권한검증결과를별도기록한다. 정상계획·EXIT·SL을인용실패만으로거절하거나재호출하지않는다.
- 모델에는 숫자를재작성하는대신 `[[TF:1h:forming:close]]` 같은기존입력의시간봉/phase/필드참조를쓰도록안내한다.
- 호스트는허용참조를동일frozen snapshot에서만해결하고정확한시간봉·phase·가격·관측시각을결합한별도공식사실표시를생성한다.
  잘못된참조/없는값/미래확정봉은UNVERIFIED다. 현재시세·다른슬롯으로대체하지않는다.
- 자유문전체는검증완료로라벨하지않는다. 명시적경로수치·단일시간봉/phase수치인용만좁게대조한다.
  정상반올림을허용하고,공동시간봉·모호한phase·예상진입가/목표가·가격범위의의미는임의추론하지않는다.
- 불일치에는원문위치·인용값·정확한원본값·근거경로를남긴다. 범위밖표현은UNASSESSED로구분한다.
- SINGLE/DRAFT후보/SELECT/no-SELECT WAIT/holding의연구응답기록에서같은검증기를사용한다. 원응답의숫자오류와호스트사실표시를구분한다.
- 검증기는거래replay envelope밖의수집/표시소비자에서만실행한다. MODEL_RAW·RESEARCH_RESULT·decision.proposal/outcome에는추가메타데이터도넣지않는다.
  최초검사실패와replay성공의차이가EXIT를차단할수있으므로,guard일치검증을느슨하게하지않고별도sidecar로격리한다.
- 실제감사소비자는 `tools/btc_explanation_evidence.py --details <보관상세JSON> --output <새sidecarJSON>`을사용한다.
  actual_request_sha256대조후공식숫자사실은sidecar의호스트값에서만인용한다. 전체자유문은미검증으로구분하고검사실패는UNKNOWN이다.
- 추가시장카탈로그를입력에중복첨부하지않고기존경로를사용한다.100KB상한·응답스키마의거래본체검증은불변이다.

## 완료 기준
1. 실제두원문및기존09:20오류를오프라인재현·검출하며정상DRAFT/다른시간봉정상값/반올림은오탐하지않는다.
2. 허용참조의공식숫자·시간봉·phase·시각이원본과일치한다. 잘못된참조는안전하게미검증으로남는다.
3. 검증기예외/원본누락/잘못된JSON이거래·보호행동의기존성공/실패분류를바꾸지않는다.
4. 원문·계약·선택·주문·손절·위험값불변,감사메타데이터의추가만확인한다.
5. 관련/전체오프라인회귀·입력크기·독립리뷰·CI를별도확인한다. 모델의자유문오류생성소멸이나매매판단정확도향상은별도미입증이다.
